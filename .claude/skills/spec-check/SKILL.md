# 実装の前の確認（確定・推測・未確定）

対象のタスク：$ARGUMENTS

（空なら、人にタスク名か課題キーを聞く。）

決まりの正本は CLAUDE.md 2章（優先順位・確定／推測／未確定）。この skill は、**ファイルを作る・直す・消すことをしない**。整理して、人に質問して、止まる。

## 1. 読む

- タスクの「もとにする設計書」（実装タスク一覧.md、API設計、画面設計、機能一覧、データ設計）の、該当する章だけ。全部は読まない。
- 関係するお手本と、同じルールを書いているほかのまとまり（貸出・確認のルール）。
- 食い違いは、CLAUDE.md 2章の優先順位で、どちらが正しいかを見る。決められないものは「未確定」にする。

## 2. 3つに分ける

| 分類 | 入れるもの | 扱い |
|---|---|---|
| 確定 | 設計書に根拠がある（ファイル・版・章を書く） | そのまま使う |
| 推測 | お手本・コード・一般的な作り方から考えた（設計書にはない） | 「推測」と書き、理由を付ける。外から見えるものは、人に確かめる |
| 未確定 | 材料が足りず決められない／設計書どうしが食い違う | 人に質問する |

## 3. 範囲と影響

- 作る・変えるもの、変えないもの。
- ほかのまとまり・common・Flyway・dao・ライブラリへの影響（CLAUDE.md 9章の「2人で共有するファイル」に当たるものは、そう書く）。
- テストで確かめる観点（設計書のどの章から）。

## 4. 質問して、止まる

外から見える判断と未確定を、**まとめて1回で**質問する（選べる質問の形で。1つの質問に選択肢を2〜4つ。推奨案を先頭に置き、理由を1文で付ける）。人の答えが出るまで、設計も実装も始めない。

次の形でまとめて見せる。

```
【確定】○○（根拠：画面設計 3章）…
【推測】○○（理由：お手本の K-03 に合わせた）…
【未確定・質問】
1. ○○について、A案（推奨）か B案か
【範囲・影響】…
```

答えが出たら、detailed-design の「設計書にない判断」の表に、判断・理由・人の確認（済＋日付）を書いて、backend-impl・frontend-impl に進む。
