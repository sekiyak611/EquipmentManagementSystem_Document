# 備品管理システム：Slack アプリ（ボット）の作成と権限付与のお願い

## お願いしたいこと

社内の Slack に、備品管理システム専用の「備品管理」ボットを1つ作って入れ、そのボットに3つの権限を与えていただきたいです。

- **ボット**：人の代わりに、システムが自動でメッセージを送るための Slack のアカウントです。

## 背景

備品管理システムは、会社の備品の貸出・返却と毎月の確認を、社員自身が Web で行えるようにする社内システムです。目的は、総務が確認状況を調べ、確認していない人に連絡する手間を減らすことです。

- システムからのお知らせは、すべて Slack の DM　で送ることにしています。

## ボットがすること・しないこと

ボットがするのは、社員本人への DM の送信だけです。内容は次のとおり。

| お知らせ | いつ送るか | 内容 |
| --- | --- | --- |
| 確認の催促 | 毎月25日 9:00（土日祝日なら前の平日） | 未確認の備品の一覧と、「自分の備品」画面へのリンク |
| アカウント登録 | 総務がユーザを登録したとき | 登録されたことと、最初のパスワードを決めるリンク（3日有効） |
| パスワード再設定 | 本人が「パスワードを忘れた」から依頼したとき | 新しいパスワードを決めるリンク（30分有効） |
| アカウントロック | パスワードを5回続けて間違えたとき | ロックしたことと、再設定のリンク |
| パスワード変更のお知らせ | パスワードを変えたとき | 変えた日時 |
| システム停止のお知らせ | システムが止まったとき | 開発者2人だけに送る |

**しないこと**

- チャンネルや、他人どうしの DM のメッセージを読みません。
- チャンネルに投稿したり、チャンネルやユーザーを作ったり消したりしません。
- ファイルを読んだり、送ったりしません。
- DM にパスワードそのものは書きません。
- AI の機能は使いません。

## 与えてほしい権限

Slack では、アプリにできることを「スコープ」という権限の単位で細かく決めます。備品管理アプリに与えるのは、次の 3 つだけです。

| スコープ | できるようになること | 使う理由 |
| --- | --- | --- |
| chat:write | ボットとしてメッセージを送る | 社員本人に DM を送るため |
| users:read.email | メンバーのメールアドレスを見る | システムに登録したメールアドレスから、DM の宛先（Slack のユーザー）を探すため |
| users:read | ワークスペースのメンバー（名前やプロフィール）を見る | Slack の決まりで、users:read.email といっしょに与える必要があるため |

- どのスコープも、メッセージの中身を読む権限ではありません。メッセージを読むには、別のスコープ（履歴を読むもの）が要り、それらは与えません。
- プロフィールとメールアドレスは、宛先を探すときに使うだけで、システムに写し取ってためておくことはしません。

## 安全面の配慮

アプリを入れると、「トークン」という合言葉が発行されます。システムはこのトークンで Slack に「備品管理アプリです」と名乗り、DM を送ります。トークンが漏れると、他人がボットになりすませるため、次のように扱います。

- トークンは、AWS のパラメータストア（秘密の値を暗号化して保管する仕組み）にだけ置きます。プログラムや GitHub、システムの記録（ログ）には書きません。
- 何かあったときは、管理者がアプリを削除すれば、その場でトークンは使えなくなります。
- 与える権限は、上の 3 つだけです。あとから権限を足すときは、改めて相談いたします。
