# 要件定義書（備品管理システム）

Nov 2, 2026 · @かいと

備品管理システムで何ができ、どんなルールで動くかをまとめた資料です。総務の皆さまに内容を確認いただき、作り始める前に合意をいただくためのものです。

## 1. この資料で合意したいこと

総務の皆さまには、とくに「7. 業務のルール」と「14. 確認したいこと」を確認いただきたいです。システムを作り始めてからルールが変わると作り直しが多くなるため、作り始める前に合意をいただきたいと考えています。

1. 全体を読み、実際の業務と合わない所があれば、コメントで教えてください。
2. 「14. 確認したいこと」に答えてください。
3. 内容に問題がなければ、「15. 合意の記録」に確認者と日付を書いてください。

この資料では、次の言葉を使います。

| 言葉 | 意味 |
| --- | --- |
| 備品 | 会社が管理する物品。今のExcelでは「機材」と呼んでいるもの |
| 管理番号 | 備品ごとの番号（例：A001） |
| 借用者 | その備品を借りている社員 |
| 最終確認日 | その備品が手元にあることを最後に確かめた日 |
| 催促 | 確認がまだの社員に、SlackのDM（1対1のメッセージ）で確認を促すこと |
| 権限 | だれがどの操作をできるかの決まり |

## 2. 背景と課題

今は、Excelの「在庫シート」と「貸出履歴シート」で備品を管理しています。このやり方には、次の課題があります。

| 課題 | 起きていること |
| --- | --- |
| 確認の手間 | 総務が備品を一つずつ確かめ、最終確認日を書き換えている |
| 連絡の手間 | 確認が漏れている人を探し、総務が個別に連絡している |
| 履歴の不備 | 借用者や貸出日の書き忘れ、返却日の書き忘れが起きる。そのため「履歴不備」を見つけて直す作業がある |
| 実態とのずれ | 記録上の借用者と、実際に持っている人が違うことがある |

## 3. 目的と範囲

備品の貸出・返却と毎月の確認を社員自身がシステムで行い、確認漏れの人にはSlackで自動的に催促します。これにより、総務が確認状況を調べる手間と、確認漏れの人に連絡する手間を減らすことが目的です。

**作るもの**

- 備品の登録・編集・廃棄・不明の管理
- 社員自身による貸出・返却の登録
- 毎月の確認（社員は自分が借りている備品、総務はだれも借りていない備品）
- 確認漏れの社員への、Slackでの自動の催促
- 総務による棚卸（備品が記録どおりにあるかを実際に確かめる作業）の支援
- ユーザと権限の管理
- 今のExcelからのデータの移行

**作らないもの**

| 作らないもの | 理由 |
| --- | --- |
| 貸出の申請・承認の流れ | 備品はだれでも自由に借りられるため |
| 備品一覧のCSV出力 | 今回は不要と判断したため |
| メールでのお知らせ | 会社のドメインが使えないため。お知らせはすべてSlackのDMで送る |
| 返却予定日を過ぎたときの催促 | 画面で赤字にするだけにする |
| QRコードによる貸出 | 今回は作らないと判断したため |
| AI機能 | 追加の費用がかかるため |
| 種別ごとに異なる項目 | 項目はすべての備品に共通にし、使わない種別では空欄にする |

## 4. 利用者と権限

利用者は「一般社員」と「総務」の2種類です。だれが何をできるか（権限）は、総務が画面から細かく作り変えられます。最初は次の2つを用意します。

| 権限 | 使う人 | できること |
| --- | --- | --- |
| 一般社員 | 社員全員 | 備品を借りる・返す。自分が借りている備品を確認する |
| 総務 | 総務の担当者 | 上に加えて、備品・種別・貸出履歴・ユーザ・権限の管理。だれも借りていない備品の確認。催促の結果を見る |

- 社員は、一人ひとり自分のメールアドレスとパスワードでログインします。
- 権限で選べる「できること」は18個です。例：備品を登録する、備品を削除する、ユーザを登録する。「備品の編集はできるが削除はできない」のような権限も作れます。
- 最初に総務として登録するのは、関谷 海仁さんです。

## 5. 業務の流れ

社員が自分で貸出・返却・確認を登録し、総務はだれも借りていない備品の確認と、記録の手直しに集中できる形に変わります。

**備品を借りる・返す（社員）**

1. 社員が「備品を借りる」画面で、保管中の備品を選んで借りる。返却予定日は入れても入れなくてもよい。
2. 借用者と貸出日は、システムが自動で入れる（書き忘れが起きない）。
3. 返すときは「自分の備品」画面で「返す」を押す。破損などがあればメモに書く。

**毎月の確認と催促**

1. 社員は、毎月25日までに、自分が借りている備品が手元にあることを確かめ、「確認した」を押す。複数あればまとめて押せる。
2. 総務は、だれも借りていない備品を確かめ、画面か、CSVでまとめて確認を登録する。
3. 25日（土日祝日なら前の平日）の9:00に、まだ確認していない社員へ、SlackのDMで自動的に催促が届く。
4. DMのリンクから「自分の備品」画面を開き、確認する。
5. 総務は「催促履歴」画面で、だれに送ったか、送れなかった人がいないかを確かめる。

**棚卸（総務）**

1. 「備品一覧」で「棚卸対象」を押すと、今のExcelと同じ条件（管理中で今月まだ確認していないもの、不明のもの）の備品が出る。色分けも今のExcelと同じ。
2. 実際に持っている人が記録と違うときは、総務が実態に合わせて返却・貸出を登録し直す。
3. 見つからない備品は「不明」、捨てた備品は「廃棄」にする。管理していない備品が見つかったら、新しく登録する。

**備品の追加・廃棄（総務）**

1. 購入や寄贈で備品が増えたら、「備品登録」画面で登録する。管理状態は「管理中」、最終確認日は登録した日になる。
2. 廃棄したら、備品の編集で管理状態を「廃棄」にし、廃棄日を入れる。貸出中の備品は、返却してからでないと廃棄できない。

## 7. 業務のルール

総務の皆さまにとくに確認いただきたい章です。実際の業務と合わないルールがあれば、コメントで教えてください。

**毎月の確認**

| No. | ルール |
| --- | --- |
| R-01 | 最終確認日が今月なら「今月確認済み」とする。今のExcelで最終確認日が黄色にならない状態と同じ |
| R-02 | 借りている備品は、借りている社員自身が確認する。だれも借りていない備品は、総務が確認する |
| R-03 | 「確認した」を押すと、最終確認日は押した日になる。社員は日付を選べない |
| R-04 | 備品を借りた日、返した日は、その備品の最終確認日もその日になる（実物を手にしたため） |
| R-05 | 総務がCSVでまとめて更新するとき、1行でも誤りがあれば何も更新しない。今の最終確認日より古い日付は反映しない |

**Slackでの催促**

| No. | ルール |
| --- | --- |
| R-06 | 毎月25日の9:00に送る。25日が土日祝日なら、前の平日に送る（例：25日が土曜なら24日の金曜。日曜なら23日の金曜。その日も祝日なら、さらに前の平日） |
| R-07 | 対象は、管理中で貸出中の備品のうち、今月まだ確認していないもの。その備品の借用者に送る |
| R-08 | 1人に1通にまとめ、未確認の備品を並べて書く |
| R-09 | 送るのは25日の1回だけ。26日以降に繰り返しは送らない |
| R-10 | だれも借りていない備品や不明の備品は、催促の対象にしない。総務が備品一覧で確かめる |
| R-11 | 送れなかった人（Slackのアカウントが見つからないなど）は催促履歴に残る。総務が本人に直接知らせる |

**貸出・返却**

| No. | ルール |
| --- | --- |
| R-12 | 借りられるのは、管理中で保管中の備品だけ。だれかが借りている備品は借りられない |
| R-13 | 人から人へ直接渡すときも、いったん返却を登録してから、次の人が借りる |
| R-14 | 社員が借りる・返すのは自分の分だけ。貸出日・返却日は登録した日になる |
| R-15 | 総務は、ほかの人の分の貸出・返却を、日付を指定して登録・修正できる（棚卸で実態と違ったときなど） |
| R-16 | 返却予定日を過ぎても催促はしない。画面で返却予定日を赤字にする |

**備品とユーザ**

| No. | ルール |
| --- | --- |
| R-17 | 管理番号は自由な形でよいが、重複はできない。登録したあとは変えられない |
| R-18 | 廃棄・不明は、削除ではなく「管理状態」の変更で行う。削除は、誤って登録したときだけ使う |
| R-19 | 貸出中の備品は廃棄・削除できない。備品を借りている人は、ユーザから削除できない |
| R-20 | 削除してもデータは消えず、「削除済み」として残る（過去の記録がだれのものか分からなくならないように） |

**パスワードとログイン**

| No. | ルール |
| --- | --- |
| R-21 | パスワードは8文字以上64文字以内。使えるのは半角の英字・数字・記号・スペース。よく使われるパスワードは使えない。定期的な変更は求めない |
| R-22 | 5回続けてパスワードを間違えるとロックされる。解除は、パスワードを再設定することでだけ行える。ロックされたら、再設定用のリンクがSlackのDMで届く |
| R-23 | パスワード再設定のリンクは30分、ユーザ登録のときのリンクは3日で使えなくなる |
| R-24 | 「ログインしたままにする」と、60日間は入り直さなくてよい。パスワードを変えると、ほかの端末のログインは切れる |

## 8. 画面

画面は19あります。社員がふだん使うのは「自分の備品」と「備品を借りる」の2画面だけで、スマートフォンでも使いやすい形にします。

| 使う人 | 画面 | スマートフォン |
| --- | --- | --- |
| だれでも | ログイン、パスワード再設定の依頼、パスワード設定 | スマートフォン優先 |
| 全員 | パスワード変更、エラー | スマートフォン優先 |
| 社員（総務も使う） | 自分の備品、備品を借りる | スマートフォン優先 |
| 総務 | 備品一覧、備品詳細、貸出履歴、催促履歴 | スマートフォンでも見られる |
| 総務 | 備品登録・編集、最終確認日の一括更新、種別管理、ユーザ一覧、ユーザ登録・編集、権限一覧、権限登録・編集、一括登録（移行） | PCで使う |

- ログインしたあと、社員には「自分の備品」、総務には「備品一覧」を最初に出します。
- 「自分の備品」では、今月まだ確認していない備品の件数と、催促の日時（例：11/25（水）9:00）を一番上に案内します。
- 「備品一覧」の色分けは今のExcelと同じです（廃棄＝灰色、不明＝青色、最終確認日が未記入か先月以前＝黄色）。

## 9. 管理する情報

備品の項目は、今のExcelの在庫シートの列をそのまま引き継ぎます。「貸出状態」と「借用者」は、今のExcelと同じく貸出履歴から自動で決まります。

| 情報 | 主な項目 |
| --- | --- |
| 備品 | 管理番号、種別、メーカー、モデル、シリアルNo、サイズ、解像度、昇降、ピボット、購入日、保証期日、廃棄日、管理状態（管理中／廃棄／不明）、最終確認日、備考 |
| 種別 | 名前、頭文字。最初は今のExcelと同じ（A：PC、B：ヘッドセット、C：マウス、D：カメラ、E：モニター、F：アダプタ） |
| 貸出履歴 | 管理番号、借用者、貸出日、返却予定日、返却日、メモ、登録した人 |
| ユーザ | 氏名、メールアドレス、権限、ロック中かどうか |
| 催促履歴 | 送った日時、宛先、対象の備品、結果（成功／失敗）、失敗の理由 |

- メールアドレスは、ログインと、SlackのDMの宛先探しに使います。Slackに登録しているメールアドレスと同じものを登録してください。
- パスワードは、元に戻せない形に変換して保存します。総務を含め、だれも他人のパスワードを見ることはできません。

## 10. Slackとの連携

お知らせはすべて、社内のSlackに入れた「備品管理」のアプリから、本人へDMで送ります。メールは送りません。

| お知らせ | いつ送るか | 内容 |
| --- | --- | --- |
| 確認の催促 | 毎月25日 9:00（土日祝日なら前の平日） | 未確認の備品の一覧と、「自分の備品」画面へのリンク |
| アカウント登録 | 総務がユーザを登録したとき | 登録されたことと、最初のパスワードを決めるリンク（3日有効） |
| パスワード再設定 | 本人が「パスワードを忘れた」から依頼したとき | 新しいパスワードを決めるリンク（30分有効） |
| アカウントロック | パスワードを5回続けて間違えたとき | ロックしたことと、再設定のリンク |
| パスワード変更のお知らせ | パスワードを変えたとき | 変えた日時。心当たりがなければ総務に連絡すること |

- どのお知らせにも、パスワードそのものは書きません。
- 社内のSlackにアプリを追加するには、Slackの管理者の承認が要る場合があります（「14. 確認したいこと」）。

## 11. 今のExcelからの移行

移すのは、ユーザ・備品・今貸出中の情報の3つです。過去の貸出履歴は移さず、今のExcelを残しておいて参照します。

1. ユーザ：氏名・メールアドレス・権限をまとめて登録する。各自は、ログイン画面の「パスワードを忘れた方はこちら」から最初のパスワードを決める。
2. 備品：在庫シートをCSV（表の各列をカンマで区切ったテキストファイル）にして取り込む。種別は管理番号の頭文字で決める。昇降・ピボットの「○」「〇」「◯」はどれも「あり」として読む。
3. 今貸出中の情報：貸出履歴シートのうち、返却日が空の行だけを取り込む。借用者は氏名でユーザと照らし合わせる。

取り込む前に、今のExcelの「履歴不備」を直しておく必要があります。同じ備品が2人に貸し出されているなど、誤りがあると取り込めず、どの行が誤りかを知らせます。

## 12. 使い勝手・安全・止まったとき（非機能要件）

機能以外に求めること（非機能要件）は、まだ「案」です。業務に合うか確認してください。

| 項目 | 案 |
| --- | --- |
| 使う端末 | スマートフォン（iPhone・Android）とPCのブラウザ。アプリのインストールは不要 |
| 使う場所 | 会社の外からも、スマートフォンで使える。インターネットに公開し、ログインで守る |
| 使える時間 | 24時間。ただし、作業のために止めることがある（前もって知らせる） |
| 止まったとき | 平日のうちに復旧することを目指す。止まっている間の貸出・返却は、動き出してから総務が日付を指定して登録できる |
| 催促が送れなかったとき | 催促の日にシステムが止まっていたら、動き出したあとの平日 9:00に送る |
| データの控え（バックアップ） | 毎日自動で取り、7日分を残す |
| 記録を残す期間 | 貸出履歴・催促履歴は消さずに残す |
| 表示の速さ | ふだん使う画面は、3秒以内に表示することを目安にする |
| 安全 | 通信は暗号化する（HTTPS）。パスワードの決まりとロック（R-21、R-22）。権限のない操作はできない。だれがいつ登録・変更したかを記録する |
| 費用 | AWS（システムを動かすクラウドサービス）の利用料が毎月かかる。金額は基本設計で見積もる |

**運用（だれが何をするか）**

| 作業 | 担当 | いつ |
| --- | --- | --- |
| ユーザの登録・削除 | 総務 | 入社・退社のとき |
| 備品の登録・廃棄 | 総務 | 購入・寄贈・廃棄のとき |
| 棚卸（だれも借りていない備品の確認） | 総務 | 毎月 |
| 催促が送れなかった人への連絡 | 総務 | 催促の日 |
| 祝日の一覧の更新 | 開発者 | 年1回（内閣府が翌年分の祝日を出したあと） |

## 13. 前提と制約

- 社員全員がSlackを使っていて、会社のメールアドレスとSlackに登録しているメールアドレスが同じである。
- 備品を複数人で共用することはない（1つの備品を借りるのは0人か1人）。
- 会社のドメイン（例：@会社名.co.jp）は使えない。そのためメールは送らず、お知らせはSlackで送る。
- AI機能は使わない。
- システムはAWSで動かす。利用料がかかることは了承済み。
- 開発は2人で、1人週2時間ほどで進める。そのため、すべての機能を一度に作り終えられない場合は、使い始める時期や順番をあらためて相談する。
