確かめたこと（詳細設計 auth/A-01_ログイン.md 4.1、common.md 3.14）：

- パスワードを間違えると失敗の回数が1増える（画面の文・401 は変わらない）。4回まではロックしない。5回目でロックし、LOCK のリンクを作り、本人にDMを1通だけ送る。
- ロック中・登録のないメールアドレス・削除されたユーザ・パスワードがまだない人は、数えない（DMも送らない）。
- ログインに成功すると回数が0に戻る。0のときは、行を書き換えない。失敗を数えても updated_by・version は変えない。
- DMが送れなくても（USER_NOT_FOUND・FAILED）、ロックはそのまま。画面の文・401 も変わらない。
- 401 を返したあとも、回数・ロック・リンクは確定して残る（まとまりを作らない、本番と同じ動きで確認）。
- リンクの合言葉は43文字、ハッシュ（SHA-256）だけを保存する。有効期限は RESET・LOCK が30分、REGISTER が3日。新しく作ると、その人の前のリンクは無効になる。

詳しいレポートは report/index.html。元の記録は results フォルダ。
画面の証跡は残していない（Client は変えていない）。

## テストの一覧（今回足した27件）

### common.passwordlink.PasswordLinkTokensTest（5件・失敗0件）

- 合言葉は43文字で、URL に使える文字（英数字・「-」「_」）だけ
- 合言葉は毎回違う（1000個で重ならない）
- ハッシュは SHA-256 の16進数・小文字の64文字（"abc" の SHA-256 と同じ値になる）
- 同じ合言葉なら同じハッシュ、違う合言葉なら違うハッシュ
- ハッシュは合言葉そのものを含まない

### common.passwordlink.PasswordLinkIssuerApiTest（6件・失敗0件）

- リンクは <app.base-url>/password-set?token=<合言葉（43文字）>
- データベースに入るのはハッシュだけ。合言葉そのものはどの列にも入らない
- 有効期限：RESET・LOCK は30分、REGISTER は3日（作った日時から）
- 新しく作ると、その人の前のリンクは無効になる（用途が違っても）。新しいリンクは有効のまま
- 使い終わったリンクの revoked_at は書き換えない。ほかの人のリンクも変えない
- 合言葉は毎回違い、ハッシュも重ならない

### api.auth.login.AuthLoginLockApiTest（13件・失敗0件）

- パスワードを間違えると、回数が1増える。画面の文・401 は変わらず、ロックもDMもない
- 4回続けて間違えても、まだロックしない（境界値）。DMもない
- 5回目の間違いでロックする。401・同じ文のまま。LOCK のリンクを作り、本人にDMを1通だけ送る
- ロックされたあとは、正しいパスワードでも 401。間違いを続けても、回数は増えず、DMも送らない
- ロックしたとき、前のリンクがあれば無効になる
- ログインに成功すると、失敗の回数が0に戻る。そのあと4回間違えても、ロックしない
- 回数が0のときにログインに成功しても、ユーザの行は書き換えない（updated_at が変わらない）
- 失敗を数えたとき、updated_by と version は変えない
- 登録のないメールアドレスで何度間違えても、だれの回数も増えない。DMもない
- パスワードがまだない人（最初の総務の担当者）は、数えない
- 削除されたユーザは、数えない
- メールアドレスの大文字・小文字がちがっても、同じユーザの失敗として数える
- ほかのユーザの回数には影響しない
