確かめたこと（詳細設計 auth/A-04_パスワード設定リンクの依頼.md）：

- 登録されているメールアドレス：202。用途 RESET のリンク（有効期限30分）を作り、本人にDM（①）を1通送る。DMのリンクの合言葉のハッシュが、保存したハッシュと同じ。パスワードも users の行も変わらない。
- 登録のない・削除されたユーザ：同じ 202・同じ文。リンクもDMも出ない。大文字・小文字は区別しない。
- 5分以内の依頼：同じ 202。リンクもDMも増えない。境界値：4分59秒前の依頼があればまだ送らず、5分1秒前なら新しいリンクを作って前のリンクを無効にする。ほかの人、ロックのリンク（LOCK）は数に入らない。
- ロック中のユーザ、パスワードがまだない人にも送る。
- DMが送れなくても（USER_NOT_FOUND・FAILED）、同じ 202・同じ文。リンクは作ったまま。
- 同じ人への依頼が6件同時に来ても、リンクは1つ、DMも1通（ユーザの行を FOR UPDATE でロックする。ロックの呼び出しを一時的に外すと、このテストが失敗することも確かめた）。
- 入力の誤り（空・形・254文字／255文字）は 400（画面設計 5章の文）。ログインなしで呼べる。CSRF の合言葉がなければ 403。

- 登録されているメールアドレス：202。RESET のリンクを作り、本人にDM（①）を1通送る
- 依頼しただけでは、パスワードは変わらない（ログインできる）。ユーザの行も書き換えない
- 登録のないメールアドレス：同じ 202・同じ文。リンクもDMも出ない
- 削除されたユーザ：同じ 202。リンクもDMも出ない
- メールアドレスの大文字・小文字は区別しない。DMの宛先は、登録しているメールアドレス
- 5分以内にもう一度依頼：同じ 202。リンクもDMも増えない
- 5分に1分足りない（4分59秒前）の依頼がある：まだ送らない（境界値）
- 5分たった（5分1秒前）の依頼がある：新しいリンクを作ってDMを送り、前のリンクは無効になる（境界値）
- ほかの人への依頼は、5分の数に入らない
- ロックのリンク（LOCK）は、5分の数に入らない。ロックされた直後でも依頼でき、前のリンクは無効になる
- ロック中のユーザにも送る。パスワードがまだない人（最初の総務の担当者）にも送る
