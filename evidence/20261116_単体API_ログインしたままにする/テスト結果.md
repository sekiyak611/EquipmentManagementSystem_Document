確かめたこと（詳細設計 common.md 3.17）：

- チェックを付けてログイン：クッキー `remember-me`（HttpOnly・60日間）と、persistent_logins の行（そのメールアドレス・番号・合言葉）ができる。付けない・rememberMe がない・false：できない。
- セッションがなくても、クッキーだけで自動ログインできる。合言葉は替わり（番号は同じ）、新しいクッキーが渡される。自動ログインのあとは、セッションで続く。権限項目はログインのときと同じ。
- 盗まれたと見る：猶予（10秒）をすぎたあとに、替える前のクッキーをもう一度使うと、401。その人の行がすべて消える（ほかの端末の分も）。
- 猶予：合言葉を替えた直後（10秒以内）に、替える前のクッキーで来ても、盗まれたとは見ない（200。合言葉は替えず、新しいクッキーも渡さない）。同じクッキーで6件が同時に来ても、全部 200 で、行は1つのまま（猶予を0にすると、この2つのテストが失敗することも確かめた）。
- 60日をすぎた（61日前）クッキー・行がない番号・削除されたユーザ・読めないクッキー（でたらめな文字）：401。クッキーは消される（500 にならない）。59日前は使える（境界値）。ロックされている人は、自動ログインできる（画面設計 2.1 の6）。
- ログアウト（A-02）：この端末の行とクッキーだけが消え、ほかの端末の分は残る。クッキーがない端末のログアウトでは、何も消えない。
- チェックを付けずにログインし直す：この端末の前のクッキーと行が消える（ほかの端末の分は残る）。別の人のクッキーがある端末で、別の人としてログインすると、ログインした人として入る。
- パスワードの再設定（A-06）：その人の行がすべて消える（ほかの人の分は残る）。パスワードの変更（A-07）：ほかの端末の分は消え、この端末が「ログインしたまま」だったときは、この端末の分だけ新しい番号で作り直す（そうでなければ作らない）。変更に失敗したときは、どれも消えない。5回間違えて、この端末をログアウトさせたときは、この端末の分だけが消える。
- 画面のファイル（/api/ でないアドレス）では、自動ログインしない。ログイン状態もクッキーもなければ、401。
- 部品（RememberMeTokenRepository）：作る・読む（ない番号は null）・合言葉と日時を新しくする・番号の行を1つだけ消す・その人の行をすべて消す。
- 既存の SecurityApiTest の1件を直した：「Spring Boot の仮のユーザを作らない」を、UserDetailsService が1つだけで、それが RememberMeUserDetailsService である、という確かめに変えた（目的は同じ。自分で作る UserDetailsService が、Bean になったため）。
