確かめたこと（詳細設計 auth/S-04_パスワード変更.md）：

- ヘッダーの氏名を押すと「パスワード変更」と「ログアウト」がこの順に出る。「パスワード変更」で /password-change に移る。ログインせずに開くとログイン画面（?redirect=）に移り、ログインするとこの画面に戻る。
- 画面設計 7章の項目と文（3つの入力欄、決まり2行、「変更する」）。現在のパスワードは `current-password`、新しいパスワードは `new-password`。横にスクロールしない。目のマークで文字を表示・隠せる。入力中に決まりの前が「・」から「✓」に変わる。
- 入力チェック（API を呼ばない）：現在のパスワードが空・新しいパスワードが空、新しいパスワードが現在と同じ、短い・長い・使えない文字（1つの欄に文を1つだけ）、確認が違う。現在のパスワードが空のときは、「現在と同じ」は出ない。
- サーバーの答え：現在のパスワードが違うと、現在のパスワードの欄の下に「現在のパスワードが違います」（この画面のまま、ログインしたまま、入力欄の値は残る）。よく使われるパスワードは、新しいパスワードの欄の下に画面設計 8章の文。400 の errors（3つの欄）を入力欄の下に出す。
- 変更できると、種別管理から開いたときは、種別管理に戻り、緑の帯「パスワードを変更しました」が出る。ログインしたまま。本人にDM（④）が届く（パスワードは書かれていない）。新しいパスワードでログインできる。直接開いたときは、最初の画面（/）に移る。
- 処理中は「変更する」を押せず、2回続けて押しても API は1回だけ。Enter でも変更できる。つながらない・403 は赤の帯（入力欄の値は残る）。401 はログイン画面に移り、ログインすると、この画面に戻る。
- 現在のパスワードを5回続けて間違えると、5回目も同じ「現在のパスワードが違います」。本人にロックのDM（③）が届き、この端末はログアウトして、画面を開き直すとログイン画面に移る。正しいパスワードでもログインできない（ロック）。
