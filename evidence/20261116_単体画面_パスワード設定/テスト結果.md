確かめたこと（詳細設計 auth/S-03_パスワード設定.md）：

- 見出し：再設定・ロックのリンクは「パスワードの再設定」、ユーザ登録のリンクは「パスワードの設定」。対象のメールアドレス、2つの入力欄（伏せ字。目のマークで切り替え。`autocomplete=new-password`）、決まり2行、「設定する」が出る。ヘッダーはシステム名だけ。横にスクロールしない。
- 入力中に、決まりの前が「・」から「✓」に変わる（8〜64文字・使える文字）。
- 入力チェック：空は「新しいパスワードを入力してください」。短い・長い・使えない文字は、1つの欄に文を1つだけ。確認が違うと確認の欄の下に「確認用のパスワードが一致しません」。どれも API を呼ばない。
- よく使われるパスワードはサーバーが断り、入力欄の下に画面設計 8章の文が出る。リンクは使えたままで、別のパスワードで設定できる。
- 設定できると、ログイン画面（/login。合言葉を含むアドレスは履歴に残さない）に移り、緑の帯「パスワードを設定しました。新しいパスワードでログインしてください。」が出る。自動ではログインしない。新しいパスワードでログインできる。
- リンクが使えないとき（正しくない合言葉・使用済み・より新しいリンクがある・アドレスに token がない）は、入力欄の代わりに「このリンクは使えません。…」と「パスワード再設定の依頼へ」（S-02 へ）が出る。開いただけでは使用済みにならない。開いたあとに使えなくなったときは、「設定する」を押すと、同じ表示に変わる。
- 処理中は「設定する」を押せず、2回続けて押しても API は1回だけ。Enter でも設定できる。
- サーバーが 400 を返したら入力欄の下に文、つながらない・403 のときは赤の帯に文を出す（入力欄の値は残る）。開いたときの確かめがつながらないときは、赤の帯だけで入力欄は出ない。
- この画面を開いている間だけ、`<meta name="referrer" content="no-referrer">` が付く。離れると外れる。
