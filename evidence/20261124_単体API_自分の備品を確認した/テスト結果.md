### api.equipment.mine.update.item.EquipmentMineUpdateItemLockTest（6件・失敗0件）

- 備品を、送られた順ではなく、ID の昇順に押さえる：小さい ID の備品を別の人が押さえている間、[大, 小] の順で送った B-04 は、大きい ID の備品を、まだ押さえていない（押さえていれば、行き違いになる）
- 場合分け③：返す人が、貸出履歴の行だけを押さえていて、備品の行はまだ：B-04 は、待たずに進み、成功する。そのあとで、返す人が進み、返す（確認が先、そのあとで返却。version は2つ増える）

- B-03（返す）と B-04（確認する）を、同じ備品に、何度同時に動かしても、デッドロックしない。どちらが先でも、つじつまが合う（返しが先なら B-04 は 403、確認が先なら両方成功）
