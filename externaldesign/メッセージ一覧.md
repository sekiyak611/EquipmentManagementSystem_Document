## 1. この資料について

画面に出すメッセージ（文）を、画面ごとに1か所に集めた資料。新しい文は作らず、画面設計・API設計に書いてある文を、そのまま写している。文を直すときは、画面設計を直し、この資料も同じに直す。

- **文の正本は、画面設計。** この資料と食い違ったら、画面設計に合わせて、この資料を直す。画面のメッセージは、画面設計の文をそのまま使う決まり（CLAUDE.md 2章）。
- 「N」「○/○」「（A001）」「（PC）」は、画面が値を入れる所（件数、日付、管理番号、種別名など）。
- 3章の「種類」は、画面設計 1.2 の3種類（完了・入力の誤り・操作できなかった）に、この資料の中で当てはめたもの。画面設計にない分け方（案内・確認のダイアログなど）も使っている。確認が要る（8章 No.1）。
- ログイン前後・ダイアログの文言そのもの（ボタンの名前や見出し）は、この資料に入れない。**ユーザに見せる「文」（メッセージ）だけ**を集めている。
- Slack の DM の文面は、インターフェース仕様書 3章と画面設計 9章にある。この資料には入れない。

## 2. 共通の決まり

### 2.1 メッセージの出し方（画面設計 1.2）

| 種類 | 出し方 | 例 |
|---|---|---|
| 完了 | 画面の上に緑の帯で出し、5秒で消える | 「借りました（A001）」 |
| 入力の誤り | 誤りのある入力欄のすぐ下に赤字で出す | 「メールアドレスを入力してください」 |
| 操作できなかった | 画面の上に赤の帯で出し、自分で閉じるまで残す | 「この備品はすでに貸し出されています」 |

### 2.2 完了の文の形

完了の文は、「○○しました（管理番号や種別名）」の形が多い（件数をまとめて知らせるものは「N件の…しました」）。

| 操作 | 文 | 画面 |
|---|---|---|
| 「確認した」を押したとき | 「確認しました（A001）」 | S-05 自分の備品 |
| 「まとめて確認した（N件）」を押したとき | 「N件の備品を確認しました」 | S-05 自分の備品 |
| 「返す」を押して、返却できたとき | 「返却しました（A001）」 | S-05 自分の備品 |
| 「借りる」を押して、借りられたとき | 「借りました（A003）」 | S-06 備品を借りる |
| 「設定する」を押して、パスワードを決められたとき | 「パスワードを設定しました。新しいパスワードでログインしてください。」 | S-03 パスワード設定 |
| 「変更する」を押して、パスワードを変えられたとき | 「パスワードを変更しました」 | S-04 パスワード変更 |
| 「確認した」を押したとき | 「確認しました（A001）」 | S-07 備品一覧 |
| 削除できたとき | 「削除しました（A001）」 | S-08 備品詳細 |
| 「登録する（登録のとき）／保存する（編集のとき）」を押したとき | 「登録しました（A001）」 | S-09 備品登録・編集 |
| 「登録する（登録のとき）／保存する（編集のとき）」を押したとき | 「保存しました（A001）」 | S-09 備品登録・編集 |

## 4. API が返す共通の message

API は、どの結果でも message を返す（API設計 2.4）。画面は、status の番号と、どの画面で起きたかで動きを決める。画面設計に文が書いてある場合は、その文を出す。次の文は、画面設計に文がないときに、API の message をそのまま使う文。

| 場面 | status | message |
|---|---|---|
| 成功 | 200・201・202 | 「処理が正常に完了しました。」 |
| 入力の誤り | 400 | 「入力内容に誤りがあります。」。入力欄ごとのメッセージは errors に入れる |
| CSVの行にエラーがある | 400 | 「エラーがあったため、更新していません。直してからもう一度アップロードしてください。」。行ごとの理由は errors に入れる |
| 決まりに合わない操作（例：貸出中の備品の削除、使われている種別の削除） | 400 | 画面設計に書いたメッセージ |
| ログインしていない | 401 | 「ログインしてください。」（A-01のログイン失敗だけは4.1の文） |
| 権限がない | 403 | 「この操作を行う権限がありません。」 |
| 見つからない | 404 | 「対象が見つかりません。」 |
| ぶつかった（ほかの人が先に保存した、すでに貸し出されている、すでに返却されている） | 409 | 画面設計に書いたメッセージ（例：「この備品はすでに貸し出されています」） |
| サーバーの不具合 | 500 | 「問題が発生しました。時間をおいて、もう一度お試しください。続く場合は総務に連絡してください。」 |
| 動いていない（A-08） | 503 | 「現在利用できません。」 |

- A-01（ログイン）の失敗だけは、401 でも message は「メールアドレスまたはパスワードが違います」（API設計 4.1）。
- S-19（エラー画面）の文は、画面の動きの文（3章）。API の message とは別。

## 6. 設計書にないメッセージ・決まっていない所（人の確認が要る）

画面の操作を一覧にして、メッセージが書いてあるかを確かめた。次の場面は、画面設計にメッセージがない。実装のとき、画面設計にない新しい文は足さず、人に確かめる決まり（CLAUDE.md 2章、react.md 5章）なので、先に決めておくと止まらない。

### 6.1 完了のメッセージがない操作

画面設計 1.2 は「完了は緑の帯」と決めているが、次の操作には、文が書いていない。

| No. | 画面 | 操作 | 画面設計の今の書き方 |
|---|---|---|---|
| 1 | S-08 | 貸出の登録、返却の登録（総務が登録するダイアログ） | 完了の文なし（11章） |
| 2 | S-10 | 履歴の修正、取り消し | 完了の文なし（13章） |
| 3 | S-14 | ユーザの削除 | 確認のダイアログの文だけ（17章） |
| 4 | S-15 | ユーザの登録（成功したとき）、保存、パスワード設定のリンクを送る | 登録して DM を送れなかったときの文だけ。成功の文なし（18章） |
| 5 | S-17 | 権限の登録、保存、削除 | 完了の文なし（20章） |
| 6 | S-18・S-20・S-21 | 一括登録の成功 | 「結果の出し方は S-11 と同じ」（21章）。ただし S-11 の文は「N件の最終確認日を更新しました。」で、登録用の文はない |

案：既存の形（「○○しました（管理番号や氏名）」）にそろえる。例：「貸出を登録しました（A001）」「返却を登録しました（A001）」「修正しました」「取り消しました」「削除しました（山田太郎）」「登録しました（山田太郎）」「保存しました（山田太郎）」「N件のユーザを登録しました」。

### 6.2 「ほかの人が先に更新した」の文が、一部の画面にしかない

API設計 2.7 は、備品・ユーザ・種別・権限・貸出履歴を変えるとき、すべてで version を確かめ、違えば 409 を返すと決めている。画面設計に文があるのは、次の画面だけ。

| 画面 | 画面設計の書き方 |
|---|---|
| S-09（備品） | 「ほかの人が先にこの備品を更新しました。画面を開き直して、最新の内容を確かめてください。」 |
| S-13（種別） | 「ほかの人が先にこの種別を更新しました。画面を開き直して、最新の内容を確かめてください。」 |
| S-15（ユーザ） | 「S-09と同じ扱い」とだけ書いてあり、文は書いていない（文は「この備品」なので、そのままは使えない） |
| S-17（権限）、S-10（貸出履歴の修正） | 書いていない |

案：「この備品」の部分を、ユーザ・権限・履歴に変えて使う（例：「ほかの人が先にこのユーザを更新しました。画面を開き直して、最新の内容を確かめてください。」）。

### 6.3 通信の失敗・ログインが切れたときの文

- ネットワークにつながらない、時間切れになった、といった通信の失敗のときに出す文は、画面設計にない（S-19 の 500 の文は、サーバーが不具合を返したときのもの）。
- 401（ログインが切れた）は、S-01 に移る（API設計 2.3）。そのとき文を出すかは、書いていない。
- 403・404 の API の message は、「この操作を行う権限がありません。」「対象が見つかりません。」（API設計 2.4）。ボタンの操作で起きたときに、画面がこの message をそのまま赤の帯に出すかは、書いていない（S-05 の詳細設計 10章 No.3 は、404 のとき「対象が見つかりません。」を赤の帯に出すと決めている）。

### 6.4 そのほか

- S-12 の「失敗の理由」は、画面設計に「例」として 2 つ（Slack のユーザーが見つからない、Slack への送信に失敗）が書いてあるだけで、理由の一覧にはなっていない。
