## 1. この資料について

権限項目（18個）と、機能・画面・API の対応を、1か所で見られるようにした資料。新しい決まりは作らず、ほかの設計書にある内容を並べ直している。

- **権限項目**とは、プログラムが「この操作をしてよいか」を確かめるときに使う名前（コード）。権限（総務・一般社員など）は、権限項目の組み合わせで、総務が画面から作り変えられる。
- 2章は「権限項目から見る」表、3章は「画面から見る」表、5章は「機能から見る」表。同じ内容を、別の向きから見ている（API は、2章と3章の列にある）。
- もとの設計書が正しい答え。この資料と食い違ったら、もとの設計書に合わせて、この資料を直す。
- 6章に、表を並べて見つけた、設計書どうしの食い違い・すき間をまとめた（人の確認が要る）。

## 4. 権限のルール

機能一覧 8章のとおり。

| No. | ルール |
|---|---|
| 1 | 権限項目の一覧はプログラムで決めておき、画面からは増やせない |
| 2 | ユーザには権限を1つだけ割り当てる |
| 3 | ユーザに割り当てている権限は削除できない |
| 4 | 「権限を管理する」を持つユーザが0人になる変更はできない |
| 5 | ユーザの権限を選べる・変えられるのは、「権限を管理する」を持つ人だけ |
| 6 | 「権限を管理する」を持たない人がユーザを登録すると、一般社員の権限が付く。そのため、一般社員の権限は削除できない |
| 7 | 権限の変更は、その権限を持つ人の次の操作から効く（ログインし直さなくてよい）。API を呼ぶたびに、サーバーが権限項目を確かめる（API設計 2.2） |

- 画面のボタンを隠すだけにせず、サーバー側でも操作のたびに確かめる（機能一覧 4章の共通ルール）。権限がなければ、API は 403 を返し、画面は S-19（権限がない）を出す。
- 「権限を見る」「権限を管理する」のコードを ROLE_ で始めないのは、Spring Security が ROLE_ で始まる名前を特別に扱うため（データ設計 5.3）。

## 6. 表を並べて見つけた食い違い・すき間（人の確認が要る）

画面を開くのに必要な権限項目（画面一覧）と、その画面が呼ぶ API に必要な権限項目（API設計）を並べて、合わないものを探した。最初に用意する権限（総務）は18個すべてを持つので、ここに挙げた問題は起きない。**総務が作り変えた権限（例：「備品を編集できるが、見られない」）で、画面が開けても、中の読み込みで 403 になる**ことがある。

| No. | 画面 | 画面を開く権限 | 合わない API | どうなるか | 案 |
|---|---|---|---|---|---|
| 1 | S-09（編集） | EQUIPMENT_CREATE か EQUIPMENT_UPDATE | C-02（備品 1 件を読む）は EQUIPMENT_VIEW が要る | EQUIPMENT_UPDATE だけを持つ人が編集を開くと、読み込みで 403 になる | 編集には EQUIPMENT_VIEW も要ると決める。または C-02 を EQUIPMENT_UPDATE でも呼べるようにする |
| 2 | S-15（編集） | USER_CREATE か USER_UPDATE | G-02（ユーザ 1 人を読む）は USER_VIEW が要る | USER_UPDATE だけを持つ人が編集を開くと、読み込みで 403 になる | 同上（USER_VIEW も要る、または G-02 を USER_UPDATE でも呼べるようにする） |
| 3 | S-17 | PERMISSION_MANAGE | H-02（権限 1 つを読む）と H-06（権限項目の一覧）は PERMISSION_VIEW が要る | PERMISSION_MANAGE だけを持つ人が S-17 を開くと、読み込みで 403 になる | 「権限を管理する」は「権限を見る」を含むと決める。または H-02・H-06 を PERMISSION_MANAGE でも呼べるようにする |
| 4 | S-14 | USER_VIEW | 探す条件の「権限」の選択肢を読む H-01 は、USER_VIEW では呼べない（PERMISSION_VIEW・USER_CREATE・USER_UPDATE のどれかが要る） | USER_VIEW だけを持つ人は、「権限」で絞り込む選択肢を読めない（画面設計 17章。API設計 3.8 の H-01 の「画面」の列に S-14 がない） | H-01 の権限に USER_VIEW を足す。または、S-14 の絞り込みで、権限の選択肢を別の方法で得る |
| 5 | S-16 → S-17 | PERMISSION_VIEW（S-16）→ PERMISSION_MANAGE（S-17） | ― | 問題なし（S-16 の「新規登録」「編集」は PERMISSION_MANAGE を持つ人にだけ出す。画面設計 19章） | ― |

- 1〜3 は、画面を開く権限と API の権限の決め方がそろっていないために起きる。どの案にするかは、設計書にまだ書いていない（API設計 2.2 の「権限の確認」は、API を呼ぶたびに確かめる、とだけ書いてある）。
- 4 は、H-01 の「画面」の列に S-14 がないため、設計書どうしの食い違い。
- 総務の権限だけで使う間は、起きない。権限を作り変える（F-15）使い方が出てから、問題になる。

## 7. 決めたこと

| No. | 決めたこと | 根拠 |

| 1 | 表は、権限項目・画面・機能の3つの向きから書く。API は、権限項目の表と画面の表の列に入れる | 人の指示（2026-11-26。「権限の対応表」） |
