## 1. このシステムでやること

- 総務が、会社の備品の情報と管理状態（管理中・廃棄・不明）を管理する。
- 社員はだれでも、保管中の備品を自分で借り、返却も自分で登録できる。
- 毎月、社員は自分が借りている備品を、総務は保管中の備品を確認し、最終確認日を記録する。
- 毎月25日（土日祝日なら前の平日）の時点で確認が終わっていない社員には、SlackのDM（1対1のメッセージ）で自動的に催促する。
- 今はExcel（在庫シート・貸出履歴シート）で行っている管理を置き換え、総務が確認状況を調べる手間と、確認漏れの人に連絡する手間を減らす。

## 3. 最初から用意する権限（案）

権限は画面から追加・変更できる（F-14・F-15）。次の2つは初期データ（システムを使い始める時点で入れておくデータ）として用意する。どの権限項目を含むかは「8. 権限のルール」の表を参照。

| 権限 | 主な利用者 | 主にすること |

| 総務 | 総務の担当者 | 備品・種別・貸出履歴・ユーザ・権限の管理。保管中の備品の確認（棚卸） |
| 一般社員 | 社員全員 | 備品を借りる・返す。自分が借りている備品の確認 |

**全機能に共通するルール**

- 削除しても、データは消さずに「削除済み」の印を付ける（論理削除）。催促履歴や貸出履歴に残った記録が、どのユーザ・どの備品のものか分からなくならないようにするため。
- 画面には、その人の権限で使えるボタンやメニューだけを表示する。表示を隠すだけでなく、サーバー側（画面の裏で動くプログラム）でも操作のたびに権限を確かめる。

## 5. 貸出・返却のルール（案）

1. 借りられるのは、管理状態が「管理中」で、貸出状態が「保管中」の備品だけ。人から人へ直接渡すときも、いったん返却を登録してから借りる。
2. 貸出状態と借用者は、今のExcelと同じく、その備品の最新の貸出履歴で決まる。最新の履歴が未返却なら「貸出中」でその人が借用者、そうでなければ「保管中」。管理中でない（廃棄・不明の）備品は、貸出状態を表示しない。
3. 一般社員が借りる・返すことができるのは、自分の分だけ。貸出日・返却日は、登録した日の日付になる（選べない）。
4. 「貸出・返却を管理する」を持つ人（総務）は、ほかの人の分も、日付を指定して登録・修正できる。棚卸で、実際に持っている人が記録と違ったときに使う。
5. 返却日は、貸出日より前にできない。
6. 貸出・返却を登録した日は、その備品の最終確認日も更新する。実物を手にしたことになるため。
7. 1〜5のチェックを入力のときに行うので、今のExcelの「履歴不備」（借用者不明・貸出日不明・過去未返却）は起きない。そのため、不備を探す機能は作らない。
8. 一般社員向けに「自分の備品」画面を作り、自分が借りている備品の一覧に、借りる（F-18）・返す（F-19）・確認した（F-07）の操作をまとめる。具体的な形は画面一覧で決める。

## 6. パスワード初期化のルール（案）

再設定用のリンクをSlackのDMで送り、リンク先の画面で本人が新しいパスワードを決める形にする（Q5の回答。送り方は画面設計v0.5のQ3でメールからSlackのDMに変えた）。OWASP（Webアプリの安全対策の指針を公開している国際的な団体）の推奨に合わせて、次のルールを付ける。

1. 画面のメッセージは、メールアドレスが登録されているかどうかにかかわらず同じにする（例：「登録されているメールアドレスであれば、再設定用のリンクを送りました」）。他人が「このアドレスは登録されているか」を調べられないようにするため。
2. 依頼しただけでは、パスワードは変えない。リンク先で新しいパスワードを決めた時点で変わる。他人が勝手に依頼しても、本人に影響が出ないようにするため。
3. リンクに含める合言葉（トークン）は、推測されにくいランダムな文字列にする。一度使ったら無効にし、有効期限を付ける（例：30分）。データベースには、元に戻せない形に変換して保存する（ハッシュ化）。
4. リンクはHTTPS（通信を暗号化する仕組み）にする。リンクのアドレスは、設定ファイル（プログラムを直さずに値を変えられるファイル）に書いた正しいアドレスで作る。アクセスしてきた側が送ってくるアドレス情報をそのまま使うと、偽のサイトへのリンクを作られるおそれがあるため。
5. リンク先の画面から別のサイトへ移ったときに、リンクのアドレス（合言葉を含む）が移った先に伝わらないようにする（Referrer-Policy という設定を no-referrer にする）。
6. 同じメールアドレスへの依頼や、合言葉の試し打ちは、短い間に何度もできないようにする（例：依頼は5分に1回まで）。
7. 新しいパスワードは2回入力して確認する。パスワードの決まり（文字数など）はF-03とF-04で同じにする。内容は画面設計の8章。
8. 再設定のあと、自動ではログインさせない（ログイン画面から入ってもらう）。ほかの端末でのログインは、すべて切る。
9. パスワードが変わったことをSlackのDMで知らせる。このDMにパスワードは書かない（F-04で変えたときも同じ）。
10. ユーザ登録（F-13）のときも、同じ仕組みでパスワード設定用のリンクを送る。有効期限は長めにする（例：3日）。
11. パスワードはそのまま保存せず、ハッシュ化して保存する。
12. 同じメールアドレスで5回続けてパスワードを間違えたら、そのユーザをロックする。解除は、パスワード再設定で新しいパスワードを決めたときだけ。ロックしたら本人にSlackのDMで知らせ、パスワード設定用のリンクを送る。詳しくは画面設計の2.1。

## 7. Slack催促のルール（案）

1. 送る日時：毎月25日 9:00。25日が土日祝日のときは、前の平日に送る（例：25日が土曜なら24日（金）、日曜なら23日（金）。その日も祝日なら、さらに前の平日）。
2. 祝日の判定：内閣府が公開している「国民の祝日」のCSVを、データベースに取り込んで使う。内閣府の説明では「原則、前年の2月に翌年度分が追加更新」されるので、取り込みは年1回、開発者が行う（画面は作らない）。
3. 対象：管理状態が「管理中」で「貸出中」の備品のうち、今月確認済みでないもの（最終確認日が未記入、または先月以前）。
4. 宛先：その備品の借用者。1人に1通にまとめ、未確認の備品を並べて書く。
5. 宛先の探し方：ユーザに登録したメールアドレスから、Slackのユーザーを探して送る。会社のメールアドレスと、Slackに登録しているメールアドレスが同じ前提。
6. 結果は、成功・失敗ともに催促履歴（F-11）に残す。
7. 送るのは月に1回だけ（26日以降に繰り返しは送らない）。ただし、催促日にシステムが止まっていて送れなかったときは、動き出したあとの平日9:00に送る（同じ月の中だけ。要件定義書12章の案。仕組みは基本設計書7章）。
8. 総務が確認する備品（保管中・不明）は、催促の対象にしない。総務は備品一覧（F-05）の絞り込みで確認する。
9. 25日を待たずにテストできるよう、送る日時は設定ファイルで変えられるようにする。

## 8. 権限のルール（案）

1. 権限項目の一覧はプログラムで決めておき、画面からは増やせない。プログラムが「この操作をしてよいか」を確かめるときに使う名前のため、項目を増やすにはプログラムの修正が要る。
2. ユーザには権限を1つだけ割り当てる。
3. ユーザに割り当てられている権限は削除できない。
4. 「権限を管理する」を持つユーザが0人になる変更はできない（だれも権限を直せなくなるのを防ぐ）。
5. ユーザの権限を選べる・変えられるのは、「権限を管理する」を持つ人だけ。「ユーザを編集する」だけの人が、自分の権限を上げられないようにするため。
6. 「権限を管理する」を持たない人がユーザを登録すると、一般社員の権限が付く。そのため、一般社員の権限は削除できない。
7. 権限の変更は、その権限を持つ人の次の操作から効く（ログインし直さなくてよい。60日間ログインしたままの人がいるため）。

## 9. 今のExcelでの運用との対応

| 今のExcelでの作業 | システムでは |
|---|---|
| 貸出時：貸出履歴シートに管理番号・借用者・貸出日（・返却予定日）を書く | F-18 貸出登録。借用者と貸出日は自動で入る |
| 返却時：返却日（・メモ）を書く | F-19 返却登録 |
| 追加時（購入・寄贈）：在庫シートに書き、管理状態を管理中にし、最終確認日を書く | F-06 備品登録。管理状態は管理中、最終確認日は登録した日になる |
| 廃棄時：廃棄日を書き、管理状態を廃棄にする | F-06 備品編集 |
| 不明時：管理状態を不明にする | F-06 備品編集 |
| 棚卸：最終確認日が黄色の管理中の備品と、不明の備品を確かめる | F-05 備品一覧の絞り込みで探し、F-07・F-09で最終確認日を更新する。借りられている備品は、社員が毎月自分で確認する（F-07・F-10） |
| 棚卸：借用者が実態と違う | 総務が、F-18・F-19で実態に合わせて返却・貸出を登録する |
| 棚卸：履歴不備を直す | 入力のときのチェックで不備が起きない（5章の7）。誤った履歴の修正はF-20 |
| 棚卸：管理していない機材があった | F-06 備品登録 |
| 管理番号の頭文字で種別が決まる | 種別は備品の項目として選ぶ。頭文字が合えば自動で選ぶ（F-06）。管理番号の形は自由。種別は総務が画面から追加できる（F-21） |
| 行や最終確認日の色分け | F-05で同じ色分けにする |
| 貸出状態・借用者・履歴不備を数式で出す | 貸出状態・借用者は最新の貸出履歴から決める（5章の2）。履歴不備は起きない |
| （Excelにはない） | 社員による毎月の確認（F-07）と、Slackでの催促（F-10）・催促履歴（F-11） |

## 10. 機能以外に必要になるもの

| もの | 内容 |
|---|---|
| HTTPS | 通信を暗号化する仕組み。ログインでパスワードを送るので必須で、パスワード設定用のリンクもHTTPSで作る。AWSのどのサービスで動かすかによっては、独自のドメインと証明書が要る |
| 開発中のSlack確認 | 開発中は、本番の社内Slackではなく、開発用に作ったSlackのワークスペース（無料で作れる）に送って確かめる |
| Slackアプリ | 社内のSlackにアプリを追加する。催促（F-10）と、パスワード関係のお知らせ（F-03・F-13）の両方に使う。スコープ（アプリに与える権限の種類）は、chat:write（メッセージを送る）と users:read.email（メールアドレスからユーザーを探す） |
| 定期実行の稼働 | 毎月25日（ずらした日）の9:00に、AWS上のアプリが動いている必要がある。費用を抑えるためにサーバーを止める運用にすると、催促が送られない |
| 祝日データ | 内閣府の「国民の祝日」CSV（1955年からの祝日を収録）を、年1回取り込む（7章の2） |
| CSVの文字コード | 文字コード＝文字をコンピュータの数値に置き換える決まり。日本語版のExcelは、保存の形式によって文字コードが変わる（「CSV（コンマ区切り）」はShift_JIS、「CSV UTF-8」はUTF-8）。テンプレートはExcelで開いても文字化けしない形で出し、取り込みはどちらの形式でも受け付ける |
