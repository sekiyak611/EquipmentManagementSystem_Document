# 実装タスク一覧（v2.0）

2026-11-03作成。2026-11-08 に、Jira のチケットの切り方（API 1本・画面1つごとのストーリー）に合わせて作り直した。設計書（確定版）をもとにした、環境構築からシナリオテストまでのタスク。

## 0. このファイルの見方

### 0.1 Jira のチケットの形

- **ストーリー**（Jira の課題の種類の1つ。1つのまとまった作業）を、次の単位で作る。
  - Claude Code が作るもの：API 1本、画面1つ、API でも画面でもない仕組み（定期実行・共通部品など）1つにつき、ストーリー1つ。
  - 人の作業と、作り終えた雛形：前の切り方のまま。ストーリー ZPOP-7・13・14・15 の下のサブタスク。
- Claude Code のストーリーには、**サブタスク**（ストーリーの中の小さな作業）を必ず4つ付ける。

| サブタスク | やること | 使う skill（Claude Code に渡す作業手順書） |
|---|---|---|
| [詳細設計] | 詳細設計を書く（形は internaldesign/詳細設計/テンプレート/） | detailed-design |
| [実装] | 作る | API・仕組み：backend-impl、画面：frontend-impl |
| [単体テスト] | 部品ごとのテストを書いて動かす（テスト方針 3章） | API・仕組み：backend-test。画面：テスト方針にないため、着手するときに中身（テストの道具を足すか、なしで閉じるか）を相談して決める |
| [結合テスト] | API・画面を通したテストを書いて動かす | API・仕組み：backend-test（テスト方針 4章）、画面：frontend-test（Playwright。テスト方針 5章） |

- **ラベル**（課題に付ける目印）で、下の1〜8章のまとまりに分けている（例：実装4_備品の管理）。Jira で「labels = 実装4_備品の管理」と探すと、その章のストーリーが出る。
- レビュー（backend-review・frontend-review）と zip づくり（deliver-zip）は、サブタスクにしていない。結合テストのあとに、人が skill を呼んで行う（CLAUDE.md 4.4）。

### 0.2 表の列

| 列 | 意味 |
|---|---|
| キー | Jira の課題キー |
| タスク名 | 作業記録のフォルダ（output/<タスク名>/）と zip（<タスク名>_<日付>.zip）の名前に使う名前（deliver-zip の skill）。API・画面は「ID_短い名前」にした。詳細設計のファイル名（<APIのID>_<短い名前>.md など）にも同じ名前を使うと探しやすい |
| 種類 | API／画面／仕組み |
| 機能 | API・仕組みは Server のパッケージ（CLAUDE.md 4.1）、画面は Client の features のフォルダ（CLAUDE.md 4.3） |
| もとにする設計書 | 着手するときに読む設計書の章。API は API設計の節と、その API を使う画面の画面設計の章（入力チェックとメッセージのもと） |
| 先にやるタスク | 先に終わっている必要があるストーリー。画面のストーリーは、ここに書いたもののほかに、すべて「雛形：画面（ZPOP-22）」のあとに始める |
