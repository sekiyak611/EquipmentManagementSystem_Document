開発用の Windows のPCに、備品管理システムの開発環境を作る手順。2人のPCで同じ版の道具を使うことを目的にする。

Claude Code の skill「env-setup」は、この手順書のとおりに1つずつ案内し、終わったかを確かめる（8章）。食い違ったときは、この手順書が正しい。

## 1. 入れるもの

### 1.1 人が入れる道具（版の決まり）

| 道具 | 版 | 決まり | 入れ方 |
|---|---|---|---|
| Docker Desktop | 最新（4.x） | 版は問わない | インストーラー（手順4）。MySQL を動かすためだけに使う |
| Java（Eclipse Temurin） | **21**（21.0.x の細かい版は問わない。新しく入れるなら、その時点の最新の 21） | 21 であること | インストーラー（MSI） |
| Node.js | **24.12.0** | この版にそろえる（package.json の決まりは 22.22.0 以上） | インストーラー（MSI） |
| Eclipse | 2025-09 以降（Pleiades All in One でもよい） | 版は問わない | 各自のやり方 |
| Git for Windows | 問わない | ― | インストーラー。Claude Code も Git に付いてくる Git Bash を使う |
| Claude Code | 最新 | ― | 手順1 |

- **LTS**（Long Term Support）は、長い期間、修正版が出続ける版のこと。
- **MSI** は、Windows の標準的なインストーラーの形式のこと。
- MySQL は PC に入れない。Docker で動かす（1.2 の表。版は compose.yaml で決まる）。

**MySQL を 8.4 にそろえる理由**

- MySQL 8.0 は、2026年4月30日に開発元のサポートが終わった。
- 本番で使う AWS の RDS for MySQL も、8.0 は2026年7月31日に標準サポートが終わり、今は有料の延長サポートでしか使えない。そのため、本番も 8.4 系にする。
- 開発のPCを本番と同じ 8.4 系にして、「自分のPCでは動くのに本番で動かない」を防ぐ。

**Docker は MySQL だけに使う**（CLAUDE.md 3章、基本設計書 9章）。Java・Node.js・Eclipse は PC に直接入れる。MySQL だけを Docker にするのは、PC に直接入れると重くなったためと、版と設定を2人で自動でそろえられるため。サーバーと画面は、Eclipse で動かしやすく、ファイルの読み書きが速いので、PC で動かす。

### 1.2 自動で同じ版になるもの

次のものは、リポジトリの中のファイルに版が書いてある。手順どおりに進めれば、だれのPCでも自動で同じ版になる。版を勝手に変えない（CLAUDE.md 3章）。

| もの | 版 | 版を決めているファイル |
|---|---|---|
| MySQL（Docker で動かす） | 8.4.13 | Server の compose.yaml（`image: mysql:8.4.13`） |
| Gradle（サーバーを組み立てる道具） | 9.8.2 | Server の gradle/wrapper/gradle-wrapper.properties |
| Spring Boot と、サーバーのライブラリ | Spring Boot 4.1.2 など | Server の build.gradle |
| 画面のライブラリ（React、MUI、Vite など） | ― | Client の package.json と package-lock.json（入れた部品の版をすべて記録したファイル） |
| Playwright（画面のテストの道具）と、テストで使うブラウザ（Chromium） | 1.63.0 | Client の package.json |

### 1.3 各自が決めること

| 項目 | 決め方 |
|---|---|
| development フォルダの場所 | 各自で決める（例：`F:\development`）。この手順書では `<development>` と書く。リポジトリをこの中に置く。ドライブ名や個人のフォルダの場所は、設計書やプログラムに書かない（CLAUDE.md 5章） |
| リポジトリを置くフォルダ | `<development>\workspace`（Eclipse のワークスペースにする） |
| MySQL の root（管理者）のパスワード | 自分で決め、Server の .env にだけ書く（手順5）。Claude Code にも会話にも書かない |
| アプリ用のユーザ `equipment` のパスワード | 自分で決める。Server の .env（手順5）と secret.yml（手順6）に、同じものを書く |

## 2. 守ること

1. **パスワードとトークン（Slack の鍵）は、Claude Code に見せない。** 会話に書かない。secret.yml と .env の中身を Claude Code に読ませない。
2. **Git の作業は人が行う。** リポジトリの取得（クローン）も人が行う（CLAUDE.md 7章）。
3. **版を変えない。** 1.1 の表と違う版を入れたいときは、先に2人で相談し、この手順書を直す（9章）。
4. 管理者の権限が要る操作（インストール、Windows の設定の変更）は、人が自分で判断して行う。

## 3. 手順

上から順に行う。各手順の「完了条件」を満たしたことを確かめてから、次に進む。コマンドは PowerShell で打つ（Server・Client のフォルダで打つものは、そのフォルダに移ってから）。

**PC に MySQL を直接入れている人は、先に5章で止める。**

### 手順1：Git と Claude Code を入れる

1. Git for Windows を入れる（https://git-scm.com/）。
2. Claude Code を入れる。コマンドプロンプト（cmd）で次を打つ（管理者の権限は要らない）。

```bat
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

3. `claude` と打ってログインする。Claude Code を使うには、有料プラン（Pro・Max・Team・Enterprise）か、Claude Console（API）のアカウントが要る。

**完了条件**：`git --version` と `claude --version` が版を表示する。

### 手順2：3つのリポジトリを並べる

GitHub から、3つのリポジトリを**同じフォルダの中に並べて**取ってくる（人が行う）。設計書の読み込みやパスは、この並び方を前提にしている（CLAUDE.md 4章）。

```
<development>\workspace
├─ EquipmentManagementSystem_Server
├─ EquipmentManagementSystem_Client
└─ EquipmentManagementSystem_Document
```

**完了条件**：3つのフォルダが、同じフォルダの中に並んでいる。

### 手順3：Java 21（Temurin）を入れる

1. https://adoptium.net/temurin/releases/ で、OS「Windows」、アーキテクチャ「x64」、種類「JDK」、版「21」の .msi をダウンロードして入れる。
2. 入れるときの機能の選択で、「Add to PATH」（どのフォルダからでも `java` で動かせるようにする設定）が有効になっていることを確かめる。

**完了条件**：新しく開いた PowerShell で `java -version` を打つと、`21.` で始まる版が出る（例：`openjdk version "21.0.13"`）。

- 古い版の Java が先に出るときは、Windows の環境変数 Path の中で、Java 21 のフォルダが上にあるかを確かめる。

### 手順4：Docker Desktop を入れる

Docker は、アプリを、そのアプリに必要なものごと「コンテナ」という箱に入れて動かす道具。この開発では、**MySQL だけ**をコンテナで動かす（サーバー・画面・Eclipse は、これまでどおり PC で動かす）。Docker Desktop は、Windows で Docker を使うためのアプリ。

**4-1. 入れる前に確かめる**

- Windows 11、または Windows 10 の 22H2 以降であること（`winver` で確かめる）。
- 会社で使うときの利用条件：Docker Desktop は、従業員 250 人未満かつ年間売上 1,000 万ドル未満の会社なら無料で使える。それより大きい会社は、有料の契約が要る。会社の規模が当てはまるかを、先に確かめる。
- 直接入れた MySQL がある人は、先に5章で止める（同じ 3306番を使うため）。

**4-2. 入れる**

1. https://www.docker.com/products/docker-desktop/ から、Windows 用（AMD64）の Docker Desktop をダウンロードして入れる（管理者の権限が要る）。
2. 入れるときの「Configuration」の画面では、「Per-user installation (Recommended)」（自分のユーザーにだけ入れる。管理者の権限が要らない）と「WSL 2」（Windows の中で Linux を動かす仕組み）を選ぶ（どちらも最初から選ばれている）。「Allow Windows Containers」は使わないので、印を付けない。古い版のインストーラーで「Use WSL 2 instead of Hyper-V」と出たら、それに印を付ける。WSL が入っていない PC では、管理者のパスワードを聞かれることがある。
3. 入れ終わったら PC を再起動し、Docker Desktop を起動する。アカウントの登録（サインイン）は、しなくても使える。
4. 「仮想化が無効」というエラーが出たら、PC の BIOS（電源を入れた直後に動く設定画面）で仮想化（Intel VT-x、AMD-V など）を有効にする。やり方は PC の機種で違う。

**4-3. 使うメモリの上限を決める（PC を重くしないため）**

Docker Desktop は、WSL 2 の中で動く。上限を決めないと、PC のメモリの半分ほどまで使うことがある。自分のユーザーのフォルダ（`%UserProfile%`。例：`C:\Users\<ユーザー名>`）に、メモ帳で `.wslconfig` という名前のファイルを作り、次を書いて保存する（「ファイルの種類」を「すべてのファイル」にし、`.wslconfig.txt` にならないようにする）。

```ini
[wsl2]
memory=2GB
```

保存したら、PowerShell で `wsl --shutdown` を打ち、Docker Desktop を起動し直す。

- MySQL のコンテナ自体も、compose.yaml で 1GB までに決めてある。2GB は、Docker Desktop が動くための分を足した値。
- PC のメモリが 16GB 以上あり、ほかでも Docker を使う人は、もっと大きくしてよい。

**4-4. PC の起動のときに Docker Desktop を自動で起動しない（任意）**

使わないときに PC を重くしたくない人は、Docker Desktop の Settings →「General」→「Start Docker Desktop when you sign in to your computer」の印を外す。外したら、開発を始めるときに自分で Docker Desktop を起動する（7章）。

**完了条件**：新しく開いた PowerShell で `docker --version` と `docker compose version` が版を表示し、`docker info` がエラーにならない（Docker Desktop が動いている）。

### 手順5：MySQL のコンテナを作る

MySQL の版（8.4.13）と設定（文字コード、照合順序、データベース equipment_dev・equipment_test、アプリ用のユーザ `equipment`）は、Server の `compose.yaml` と `docker/mysql/init/` に書いてある。2人のPCで、自動で同じになる。

**5-1. .env を作る**

1. Server のフォルダで、`.env.example` をコピーして `.env` を作る。
2. `MYSQL_ROOT_PASSWORD`（MySQL の root＝管理者のパスワード）と `MYSQL_PASSWORD`（アプリ用のユーザ `equipment` のパスワード）を、自分で決めて書く。
3. `MYSQL_PORT` は 3306 のままにする。

- .env は Git で管理しない（.gitignore に入っている）。**Claude Code に中身を見せない。会話に書かない。**
- `MYSQL_PASSWORD` は、手順6で secret.yml にも同じものを書く。

**5-2. コンテナを作って起動する**

Server のフォルダで次を打つ。

```powershell
docker compose up -d
```

- 最初は、MySQL のイメージ（コンテナのもとになるファイル一式。展開すると約 1.1GB）のダウンロードで数分かかる。
- 最初の起動のときだけ、データベース2つとユーザ `equipment` が作られる。データは、Docker の「ボリューム」（コンテナを消しても残るデータの置き場所）に入る。
- `-d` は、裏で動かす指定。PowerShell を閉じても MySQL は動き続ける。

**5-3. 動いているかを確かめる**

```powershell
docker compose ps
```

STATUS が `healthy` になるまで、30秒ほど待つ（`starting` の間は、まだ準備中）。

**完了条件**：`docker compose ps` で `equipment-mysql` の STATUS が `healthy` になる。

- 中を見たいときは、`docker compose exec mysql mysql -u equipment -p` と打ち、5-1 で決めた `MYSQL_PASSWORD` を入れる（`SHOW DATABASES;` で equipment_dev と equipment_test が出る。`exit` で抜ける）。

### 手順6：secret.yml を作る

1. Server のフォルダで、`secret.example.yml` をコピーして `secret.yml` を作る。
2. `spring.datasource` の `username` に `equipment`、`password` に手順5で .env の `MYSQL_PASSWORD` に書いたものと同じパスワードを書く。
3. Slack のトークン（`app.slack.bot-token`）と最初の総務の担当者のメールアドレス（`app.initial-admin-email`）は、使うタスクになってから書く。

secret.yml は Git で管理しない（.gitignore に入れる）。サーバー（Spring Boot）は .env を読まないので、secret.yml にも書く。

**完了条件**：Server のフォルダ（build.gradle と同じフォルダ）に secret.yml がある。

### 手順7：サーバーのテストと起動を確かめる

Server のフォルダで次を打つ。

```powershell
.\gradlew.bat test
```

最初は Gradle と部品のダウンロードで数分かかる。`BUILD SUCCESSFUL` が出ればよい。

続けて、`.\gradlew.bat bootRun` でサーバーを起動し、ブラウザで http://localhost:8080/api/health を開く。確かめたら `Ctrl + C` で止める。

**完了条件**：テストで `BUILD SUCCESSFUL` が出る。/api/health で `"state":"UP"` を含む文が出る。

### 手順8：Node.js 24.12.0 を入れる

1. https://nodejs.org/dist/v24.12.0/ から `node-v24.12.0-x64.msi` をダウンロードして入れる。ダウンロードしたファイルが正しいかは、同じ場所の `SHASUMS256.txt` の値と比べて確かめられる（`Get-FileHash .\node-v24.12.0-x64.msi`）。
2. PowerShell で `npm` を使えるようにする。Windows の初期の設定では、PowerShell は署名のないスクリプトを動かさないため、`npm`・`npx` が「デジタル署名されていません」というエラーになる。PowerShell で次を1回だけ打つ（今のユーザだけの設定。管理者の権限は要らない）。

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

   RemoteSigned は、「インターネットから取ってきたスクリプトは署名が要る。自分のPCにあるスクリプトは動かしてよい」という設定。この設定を変えたくない人は、代わりに `npm.cmd`・`npx.cmd` と打つか、コマンドプロンプト（cmd）で打つ。

**完了条件**：`node -v` が `v24.12.0`、`npm -v` が版を表示する。

### 手順9：画面の部品を入れる

Client のフォルダで次を打つ。

```powershell
npm install
npx playwright install chromium
```

**完了条件**：どちらもエラーなく終わる。

### 手順10：画面のテストを確かめる

開発用に起動したサーバーがあれば、先に止める。Playwright は、すでに動いているサーバーをそのまま使うため、開発用のデータベース（equipment_dev）でテストが動いてしまう。

Client のフォルダで次を打つ。

```powershell
npx playwright test
```

テスト用の設定（equipment_test）でサーバーと画面が自動で起動し、テストが動く。

**完了条件**：すべて `passed` になる。

### 手順11：Eclipse に Server を取り込む

1. 「ウィンドウ」→「設定」→「Gradle」で、「Java ホーム」に Java 21 のフォルダを指定する（Gradle 9 は Java 17 以上で動く。取り込みでエラーが出るときは、ここを確かめる）。
2. 「ファイル」→「インポート」→「Gradle」→「既存の Gradle プロジェクト」で、Server のフォルダを指定する。
3. プロジェクト名が、フォルダ名と同じ `EquipmentManagementSystem_Server` になっていることを確かめる（Server の CLAUDE.md 2章）。

画面（Client）は、VS Code など好きなエディタで開いてよい。

**完了条件**：Eclipse のプロジェクトに、エラーの印（赤い×）がない。

### 手順12：Claude Code の設定

1. Document の `internaldesign/settings.json` を、Server と Client の `.claude/settings.json` に写す（`.claude` フォルダがなければ作る）。Claude Code が git・gh のコマンドを動かせないようにする、念のための設定（CLAUDE.md 7章）。
2. Server のフォルダで `claude --add-dir ../EquipmentManagementSystem_Document` と打って起動し、`/` を打つ。

**完了条件**：skill の一覧に、backend-impl・frontend-impl・env-setup などが出る。

### 手順13：Git で管理しないものを確かめる

各リポジトリ（Server・Client・Document）に .gitignore があり、Server・Client の CLAUDE.md 4章の一覧（secret.yml、logs/、build/、node_modules/、output/ など）が入っているかを確かめる。足りなければ Claude Code が足す（CLAUDE.md 7章）。とくに **secret.yml が入っていることを、最初のコミットの前に必ず確かめる**。

**完了条件**：一覧のものが、すべて .gitignore に入っている。

## 5. PC に直接入れた MySQL を止める（すでに入れている人）

Docker の MySQL は、PC の 3306番を使う。PC に直接入れた MySQL（8.0 や、前の手順書で入れた 8.4.13 の MySQL84 など）が動いていると、ぶつかって起動しない。

テーブルは Flyway が作り直すので、PC の MySQL に残すべきデータはない（開発用に手で入れたデータは消える。要るものがあれば、先に人が控える）。

1. サーバー（bootRun・Eclipse）を止める。
2. PowerShell で `Get-Service *mysql*` を打ち、動いている MySQL のサービスの名前（例：`MySQL84`、`MYSQL80`）を確かめる。
3. PowerShell を「管理者として実行」で開き、次を打つ（`MySQL84` の所は、2で確かめた名前にする）。

```powershell
Stop-Service MySQL84
Set-Service MySQL84 -StartupType Disabled
```

   `Disabled` は、PC を起動しても動かないようにする設定。止めるだけで足りる（消すのは4。任意）。

4. 要らなくなったら、消してよい（任意）。
   - インストーラーで入れた MySQL：Windows の「設定」→「アプリ」からアンインストールする。データのフォルダ（初期値は `C:\ProgramData\MySQL\MySQL Server <版>`。ProgramData は隠しフォルダ）は残るので、要らなければ人が消す。
   - zip で入れた MySQL（前の手順書の手順4）：管理者の PowerShell で `& "<development>\mysql-8.4.13-winx64\bin\mysqld.exe" --remove MySQL84` を打ってサービスを消し、`<development>` の `mysql-8.4.13-winx64` と `mysql-data` のフォルダを消す。
   - Windows の環境変数 Path から、MySQL の bin のフォルダを外す。
5. 手順4〜7を行う。

**完了条件**：`Get-Service *mysql*` で、`Running` の MySQL がない（何も出ないか、`Stopped`）。

## 6. つまずきやすい点

| 出たもの | 原因と直し方 |
|---|---|
| `docker` が見つからない、`docker info` が `error during connect` などで失敗する | Docker Desktop が動いていない。スタートメニューから Docker Desktop を起動し、左下が緑（Engine running）になるまで待つ |
| `docker compose up -d` で `.env に MYSQL_ROOT_PASSWORD を書いてください` と出る | Server のフォルダに .env がない、または値が空。手順5-1 |
| `docker compose up -d` で `ports are not available`・`address already in use`（3306） | PC に直接入れた MySQL が 3306番を使っている。5章で止める |
| 「仮想化が無効」「WSL 2 が入っていない」と出て Docker Desktop が起動しない | 手順4-2 の4（BIOS の仮想化）。WSL が古いときは、PowerShell で `wsl --update` を打つ |
| PC が重い | 手順4-3 の .wslconfig のメモリの上限を確かめる。使わないときは `docker compose stop` で MySQL を止め、Docker Desktop も終わらせる（7章） |
| `Communications link failure` | MySQL が動いていない、または準備中。Docker Desktop を起動し、Server のフォルダで `docker compose up -d` → `docker compose ps` で `healthy` になるまで待つ |
| `Access denied for user 'equipment'` | secret.yml のパスワードが、.env の `MYSQL_PASSWORD` と違う。または secret.yml の場所が違う（build.gradle と同じフォルダに置く）。**コンテナを作ったあとで .env のパスワードを変えても、MySQL の中のパスワードは変わらない**（最初の起動のときだけ使われるため）。変えたいときは、`docker compose down -v`（データも消える）→ `docker compose up -d` で作り直す |
| equipment_test がない（テストが `Unknown database 'equipment_test'` で失敗する） | 最初の起動の前に docker/mysql/init がなかった（古い Server で作った）など。`docker compose down -v` → `docker compose up -d` で作り直す |
| テストがほぼ全部失敗し、`ConflictingBeanDefinitionException`（例：bean name 'healthMapper' … conflicts）と出る | 同じ名前のクラスが、古い場所と新しい場所の両方にある。成果物の zip を反映したときに、変更ファイル一覧.md の「消した」ファイルを消し忘れている。そのファイルを消してから、もう一度テストする |
| テストの名前などの日本語が、PowerShell の画面で文字化けする | 画面の文字コードの違いで、テストの結果には影響しない。レポート（build/reports/tests/test/index.html）では正しく読める。気になるときは、テストの前に `chcp 65001` を打つと直ることが多い |
| `java -version` が 21 でない | Path の中で、ほかの版の Java が上にある。Java 21 のフォルダを上に移し、PowerShell を開き直す |
| `npm`・`npx` が「デジタル署名されていません」 | PowerShell の実行ポリシー。手順8の2 |
| `Access denied for user '（Windows のユーザー名）'@'localhost' (using password: NO)`（例：テストがほぼ全部失敗し、原因に FlywaySqlUnableToConnectToDbException と出る） | secret.yml がない、または置き場所が違う。ユーザ名が書かれていないので、Windows のユーザー名でつなごうとしている。手順6のとおり、Server のフォルダ（build.gradle と同じフォルダ）に secret.yml を作る |
| `Public Key Retrieval is not allowed` | MySQL 8.4 のパスワードのやり取りの決まり（caching_sha2_password）による。DBViewer などの道具でつなぐときは、接続の文字列の後ろに `?allowPublicKeyRetrieval=true` を足す（アプリの設定は変えない） |
| `Port 8080 was already in use` | 8080番を使う別のアプリ（起動したままのサーバーなど）がある。止めてから起動する |
| Playwright のテストが、開発用のデータで動く・データが消える | 開発用に起動したサーバーを、Playwright がそのまま使った。止めてから `npx playwright test` |
| Eclipse で取り込めない・名前の食い違いのエラー | プロジェクト名とフォルダ名が違う。settings.gradle の `rootProject.name` がフォルダ名と同じかを確かめる（変えない決まり） |
| Eclipse の Gradle で Java のエラー | 手順11の1（Gradle の Java ホームを Java 21 にする） |

## 7. 毎日の開発の始め方

- MySQL：Docker Desktop を起動し（PC の起動のときに自動で起動していれば要らない）、Server のフォルダで `docker compose up -d`。コンテナが動いたままなら、何もしなくてよい。
- サーバー：Server のフォルダで `.\gradlew.bat bootRun`、または Eclipse で EquipmentApplication を右クリック →「実行」→「Spring Boot アプリケーション」。
- 画面：Client のフォルダで `npm run dev` → http://localhost:5173 を開く。
- Claude Code：Server か Client のフォルダで `claude --add-dir ../EquipmentManagementSystem_Document`。
- 終わるとき：Server のフォルダで `docker compose stop`（MySQL を止める。データは残る）。そのあと Docker Desktop を終わらせると、PC のメモリが空く。

| コマンド（Server のフォルダで） | すること | データ |
|---|---|---|
| `docker compose up -d` | MySQL を起動する（なければ作る） | 残る |
| `docker compose stop` | MySQL を止める | 残る |
| `docker compose down` | MySQL のコンテナを消す（次の `up -d` で作り直す） | 残る（ボリュームは消えない） |
| `docker compose down -v` | コンテナとデータを両方消す | **消える**（次の `up -d` で、データベースとユーザを作り直す。テーブルはサーバーの起動で Flyway が作る） |

## 8. Claude Code に案内してもらう場合

1. 手順1・2は人が行う（Claude Code を入れ、リポジトリを並べる）。
2. Document のフォルダで `claude` と打って起動し、`/env-setup` と打つ。Server・Client がまだ動かなくても使える。
3. Claude Code が、終わっていない手順を見つけて1つずつ案内する。インストールや管理者の操作は人が行い、終わったら Claude Code が確かめのコマンドを動かす。
4. パスワードは会話に書かない（2章）。

## 9. 版を上げるとき

1. 2人で相談して、新しい版を決める。MySQL は、本番（RDS）で使える 8.4 系の版から選ぶ。
2. 1.1・1.2 の表と、手順の中の版を書き換える。MySQL の版は、Server の compose.yaml の `image: mysql:<版>` を書き換える（Server のプルリクエストにする）。
3. env-setup の skill（Document の .claude/skills/env-setup/SKILL.md）の版も合わせて直す。
4. 1人が自分のPCで入れ替え、4章のチェックリストがすべて通ることを確かめてから、もう1人に知らせる。

MySQL を 8.4 系の中で上げる場合（例：8.4.13 → 8.4.14）、データはそのまま使える。compose.yaml の版を変えたものを取ってきたら、Server のフォルダで `docker compose up -d` を打つ（新しい版のイメージを取ってきて、コンテナを作り直す。ボリュームのデータはそのまま）。
