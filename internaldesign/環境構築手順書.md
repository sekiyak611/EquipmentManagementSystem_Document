開発用の Windows のPCに、備品管理システムの開発環境を作る手順。2人のPCで同じ版の道具を使うことを目的にする。

Claude Code の skill「env-setup」は、この手順書のとおりに1つずつ案内し、終わったかを確かめる（8章）。食い違ったときは、この手順書が正しい。

## 1. 入れるもの

### 1.1 人が入れる道具（版の決まり）

| 道具 | 版 | 決まり | 入れ方 |
|---|---|---|---|
| MySQL Community Server | **8.4.13**（LTS） | **この版にそろえる** | zip を development フォルダに展開して入れる（インストーラーは使わない）。3306番で、Windows のサービス（PCの起動で自動で動くプログラム）として動かす |
| Java（Eclipse Temurin） | **21**（21.0.x の細かい版は問わない。新しく入れるなら、その時点の最新の 21） | 21 であること | インストーラー（MSI） |
| Node.js | **24.12.0** | この版にそろえる（package.json の決まりは 22.22.0 以上） | インストーラー（MSI） |
| Eclipse | 2025-09 以降（Pleiades All in One でもよい） | 版は問わない | 各自のやり方 |
| Git for Windows | 問わない | ― | インストーラー。Claude Code も Git に付いてくる Git Bash を使う |
| Claude Code | 最新 | ― | 手順1 |

- **LTS**（Long Term Support）は、長い期間、修正版が出続ける版のこと。
- **MSI** は、Windows の標準的なインストーラーの形式のこと。
- MySQL を zip で入れるのは、置き場所と設定を手順書のとおりにそろえやすく、PCのほかの場所を汚さないため。すでにインストーラーで 8.4.13 を入れ、3306番のサービスで動いている人は、そのまま使ってよい（版・ポート・動かし方が同じなので、開発には差がない）。

**MySQL を 8.4 にそろえる理由**

- MySQL 8.0 は、2026年4月30日に開発元のサポートが終わった。
- 本番で使う AWS の RDS for MySQL も、8.0 は2026年7月31日に標準サポートが終わり、今は有料の延長サポートでしか使えない。そのため、本番も 8.4 系にする。
- 開発のPCを本番と同じ 8.4 系にして、「自分のPCでは動くのに本番で動かない」を防ぐ。

**Docker は使わない**（CLAUDE.md 3章、基本設計書 v1.3 の9章）。道具はPCに直接入れる。2026-11-09〜11-14 の間は MySQL だけを Docker で動かしていたが、やめた。Docker で動かしていた人は、5章で片づける。

### 1.2 自動で同じ版になるもの

次のものは、リポジトリの中のファイルに版が書いてある。手順どおりに進めれば、だれのPCでも自動で同じ版になる。版を勝手に変えない（CLAUDE.md 3章）。

| もの | 版 | 版を決めているファイル |
|---|---|---|
| Gradle（サーバーを組み立てる道具） | 9.8.2 | Server の gradle/wrapper/gradle-wrapper.properties |
| Spring Boot と、サーバーのライブラリ | Spring Boot 4.1.2 など | Server の build.gradle |
| Lombok（コンストラクタやゲッターなどを、`@` で始まる印＝アノテーションで自動で作る部品） | Spring Boot が決めた版（2026-11-15 時点で 1.18.48） | Server の build.gradle（Spring Boot が決める）。**Eclipse には、手順11の4で同じ版を人が入れる** |
| MyBatis Generator（テーブルから Mapper などを自動で作る道具） | 2.0.0 | Server の build.gradle。`.\gradlew.bat mybatisGenerator` で動く。PC に入れるものはない |
| 画面のライブラリ（React、MUI、Vite など） | ― | Client の package.json と package-lock.json（入れた部品の版をすべて記録したファイル） |
| Playwright（画面のテストの道具）と、テストで使うブラウザ（Chromium） | 1.63.0 | Client の package.json |

### 1.3 各自が決めること

| 項目 | 決め方 |
|---|---|
| development フォルダの場所 | 各自で決める（例：`F:\development`）。この手順書では `<development>` と書く。MySQL とリポジトリをこの中に置く。ドライブ名や個人のフォルダの場所は、設計書やプログラムに書かない（CLAUDE.md 5章） |
| リポジトリを置くフォルダ | `<development>\workspace`（Eclipse のワークスペースにする） |
| MySQL の root（管理者）のパスワード | 自分で決め、自分だけが持つ。Claude Code にも会話にも書かない |
| アプリ用のユーザ `equipment` のパスワード | 自分で決める。Server の secret.yml にだけ書く（手順6） |

## 2. 守ること

1. **パスワードとトークン（Slack の鍵）は、Claude Code に見せない。** 会話に書かない。secret.yml の中身を Claude Code に読ませない。
2. **Git の作業は人が行う。** リポジトリの取得（クローン）も人が行う（CLAUDE.md 7章）。
3. **版を変えない。** 1.1 の表と違う版を入れたいときは、先に2人で相談し、この手順書を直す（9章）。
4. 管理者の権限が要る操作（インストール、Windows の設定の変更）は、人が自分で判断して行う。

## 3. 手順

上から順に行う。各手順の「完了条件」を満たしたことを確かめてから、次に進む。コマンドは PowerShell で打つ（Server・Client のフォルダで打つものは、そのフォルダに移ってから）。

**すでに MySQL 8.0 を入れている人は、先に5章で 8.4 に入れ替える。**

### 手順1：Git と Claude Code を入れる

1. Git for Windows を入れる（https://git-scm.com/）。
2. Claude Code を入れる。コマンドプロンプト（cmd）で次を打つ（管理者の権限は要らない）。

```bat
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

3. `claude` と打ってログインする。Claude Code を使うには、有料プラン（Pro・Max・Team・Enterprise）か、Claude Console（API）のアカウントが要る。

**完了条件**：`git --version` と `claude --version` が版を表示する。

### 手順2：3つのリポジトリを並べる

GitHub から、3つのリポジトリを**同じフォルダの中に並べて**取ってくる（人が行う）。設計書の読み込みやパスは、この並び方を前提にしている（CLAUDE.md 4章）。

```
<development>\workspace
├─ EquipmentManagementSystem_Server
├─ EquipmentManagementSystem_Client
└─ EquipmentManagementSystem_Document
```

**完了条件**：3つのフォルダが、同じフォルダの中に並んでいる。

### 手順3：Java 21（Temurin）を入れる

1. https://adoptium.net/temurin/releases/ で、OS「Windows」、アーキテクチャ「x64」、種類「JDK」、版「21」の .msi をダウンロードして入れる。
2. 入れるときの機能の選択で、「Add to PATH」（どのフォルダからでも `java` で動かせるようにする設定）が有効になっていることを確かめる。

**完了条件**：新しく開いた PowerShell で `java -version` を打つと、`21.` で始まる版が出る（例：`openjdk version "21.0.13"`）。

- 古い版の Java が先に出るときは、Windows の環境変数 Path の中で、Java 21 のフォルダが上にあるかを確かめる。

### 手順4：MySQL 8.4.13 を development フォルダに入れる

**4-1. zip をダウンロードして確かめる**

1. https://dev.mysql.com/downloads/mysql/ で、版「8.4.13」、OS「Microsoft Windows」の「Windows (x86, 64-bit), ZIP Archive」（ファイル名 `mysql-8.4.13-winx64.zip`。「Debug Binaries & Test Suite」ではない方）をダウンロードする。
   - 新しい版が出て一覧から消えていたら、https://downloads.mysql.com/archives/community/ から 8.4.13 を探す。
2. ファイルが正しいかを確かめる。MD5（ファイルの中身から計算する値。1バイトでも違えば別の値になる）を、公式のダウンロードページの値と比べる。

```powershell
Get-FileHash .\mysql-8.4.13-winx64.zip -Algorithm MD5
```

   `7B94489D5524DEA9B27097068BEA25A8` と同じなら正しい。違ったら使わず、ダウンロードし直す。

**4-2. development フォルダに展開する**

zip を `<development>` に展開する（エクスプローラーで右クリック →「すべて展開」で、展開先に `<development>` を指定）。展開できたら、次の形になっている。

```
<development>
├─ mysql-8.4.13-winx64\     MySQL の本体（bin\mysqld.exe などがある）
├─ mysql-data\              データの置き場所（空のフォルダを自分で作る。中の equipment は 4-4 で MySQL が作る）
└─ workspace\               リポジトリ（手順2）
```

フォルダが `mysql-8.4.13-winx64\mysql-8.4.13-winx64\bin` のように二重になったら、中の方を `<development>` の直下に移す。あわせて、`<development>` の中に、空の `mysql-data` フォルダを作る。

**4-3. 設定ファイル（my.ini）を作る**

メモ帳で次の内容のファイルを作り、`<development>\mysql-8.4.13-winx64\my.ini` という名前で保存する。メモ帳で保存するときは、「ファイルの種類」を「すべてのファイル」にし（`my.ini.txt` にならないように）、文字コードは「UTF-8」（BOM なし）にする。`<development>` の所は、自分のフォルダに書き換える。フォルダの区切りは `/` で書く（例：`F:/development`）。

```ini
[mysqld]
basedir=<development>/mysql-8.4.13-winx64
datadir=<development>/mysql-data/equipment
port=3306
bind-address=127.0.0.1
```

- `basedir` は MySQL の本体の場所、`datadir` はデータの置き場所。
- `bind-address=127.0.0.1` は、このPCからの接続だけを受け付ける設定。

**4-4. データの置き場所を作る（初期化）**

PowerShell で次を打つ（`<development>` は自分のフォルダに書き換える）。

```powershell
& "<development>\mysql-8.4.13-winx64\bin\mysqld.exe" --defaults-file="<development>\mysql-8.4.13-winx64\my.ini" --initialize-insecure --console
```

`--initialize-insecure` は、root（管理者）のパスワードを空にして初期化する指定。パスワードは手順5の最初で決める。それまでは、`bind-address` のとおり、このPCからしかつながらない。

**4-5. Windows のサービスに登録して起動する**

PowerShell を「管理者として実行」で開き（スタートメニューで PowerShell を右クリック）、次を打つ。

```powershell
& "<development>\mysql-8.4.13-winx64\bin\mysqld.exe" --install MySQL84 --defaults-file="<development>\mysql-8.4.13-winx64\my.ini"
net start MySQL84
```

- `--install MySQL84` は、MySQL を「MySQL84」という名前で Windows のサービスに登録する指定。PCを起動すると、自動で動くようになる。
- 登録が終わったら、管理者の PowerShell は閉じる。

**4-6. Path に足す**

Windows の環境変数 Path（どのフォルダからでもコマンドを動かせるようにする設定）に、`<development>\mysql-8.4.13-winx64\bin` を足す。

1. スタートメニューで「環境変数」と探し、「環境変数を編集」（自分のユーザーの環境変数）を開く。
2. 「Path」を選んで「編集」→「新規」で、上のフォルダを足す。
3. MySQL 8.0 など、ほかの MySQL の bin が Path に残っていたら外す。

**完了条件**：新しく開いた PowerShell で、次の2つを確かめる。

- `mysql --version` を打つと `Ver 8.4.13` を含む行が出る。
- `Get-Service *mysql*` を打つと、`MySQL84` が `Running` になっている。

### 手順5：データベースとアプリ用のユーザを作る

PowerShell で `mysql -u root --skip-password` を打ってつなぐ（4-4 で root のパスワードを空にしたため）。つながったら、次の SQL を流す。1行目で root のパスワードを決める。パスワードの所は、自分で決めた文字に置き換える。**この SQL をパスワードごと会話や Claude Code に貼らない。**

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '（root のパスワード。自分で決める）';
CREATE DATABASE equipment_dev  CHARACTER SET utf8mb4 COLLATE utf8mb4_ja_0900_as_cs_ks;
CREATE DATABASE equipment_test CHARACTER SET utf8mb4 COLLATE utf8mb4_ja_0900_as_cs_ks;
CREATE USER 'equipment'@'localhost' IDENTIFIED BY '（equipment のパスワード。自分で決める）';
CREATE USER 'equipment'@'127.0.0.1' IDENTIFIED BY '（同じパスワード）';
CREATE USER 'equipment'@'::1'       IDENTIFIED BY '（同じパスワード）';
GRANT ALL PRIVILEGES ON equipment_dev.*  TO 'equipment'@'localhost', 'equipment'@'127.0.0.1', 'equipment'@'::1';
GRANT ALL PRIVILEGES ON equipment_test.* TO 'equipment'@'localhost', 'equipment'@'127.0.0.1', 'equipment'@'::1';
```

- インストーラーで MySQL を入れた人は、root のパスワードを決めてあるので、`mysql -u root -p` でつなぎ、1行目（ALTER USER）を飛ばす。
- ユーザ `equipment` を3つ作るのは、MySQL が、つなぐ元の呼び名（localhost・127.0.0.1・::1）ごとに、別のユーザとして扱うため。アプリが自分のPCにつなぐときに、どの呼び名に見えるかは PC の設定で変わるので、3つとも作る。パスワードは3つとも同じにする。`::1` は、IPv6（新しい形のアドレス）での「自分自身」。Linux の確かめでは、`::1` からのつなぎは試せなかった（ユーザを作るところまで）。
- equipment_dev は開発用、equipment_test は自動テスト専用（テストのたびに Flyway がテーブルを消して作り直す）。2つを分ける（CLAUDE.md 6章）。
- 照合順序（文字の比べ方の決まり）は utf8mb4_ja_0900_as_cs_ks（データ設計 2章）。

**完了条件**：8行とも、エラーなく `Query OK` が出る。`exit` で抜ける。次からは `mysql -u root -p` で、決めたパスワードを入れてつなぐ。続けて `mysql -u equipment -p -e "SHOW DATABASES;"` を打ち、`equipment` のパスワードを入れると、`equipment_dev` と `equipment_test` が出る。

### 手順6：secret.yml を作る

1. Server のフォルダで、`secret.example.yml` をコピーして `secret.yml` を作る。
2. `spring.datasource` の `username` に `equipment`、`password` に手順5で決めた `equipment` のパスワードを書く（root のパスワードではない）。
3. `app.initial-admin-email` に、メールアドレスの形（`@` を1つ含み、空白や `'` `"` `\` を含まない）の値を書く。自分のメールアドレスか、`admin@example.com` のようなダミーでよい。**最初にサーバーを起動するとき（手順7）に空だと、サーバーが起動しない**（データベースに最初のデータを入れるために要る）。`soumu@example.com`・`ippan@example.com` は、開発用のユーザー（詳細設計 common.md 4章）が使うので、避ける。
4. Slack のトークン（`app.slack.bot-token`）は、空のままでよい（Slack の通知を使うタスクになってから書く）。

secret.yml は Git で管理しない（.gitignore に入れる）。

**完了条件**：Server のフォルダ（build.gradle と同じフォルダ）に secret.yml がある。

### 手順7：サーバーのテストと起動を確かめる

Server のフォルダで次を打つ。

```powershell
.\gradlew.bat test
```

最初は Gradle と部品のダウンロードで数分かかる。`BUILD SUCCESSFUL` が出ればよい。

続けて、`.\gradlew.bat bootRun` でサーバーを起動し、ブラウザで http://localhost:8080/api/health を開く。確かめたら `Ctrl + C` で止める。

**完了条件**：テストで `BUILD SUCCESSFUL` が出る。/api/health で `"state":"UP"` を含む文が出る。

### 手順8：Node.js 24.12.0 を入れる

1. https://nodejs.org/dist/v24.12.0/ から `node-v24.12.0-x64.msi` をダウンロードして入れる。ダウンロードしたファイルが正しいかは、同じ場所の `SHASUMS256.txt` の値と比べて確かめられる（`Get-FileHash .\node-v24.12.0-x64.msi`）。
2. PowerShell で `npm` を使えるようにする。Windows の初期の設定では、PowerShell は署名のないスクリプトを動かさないため、`npm`・`npx` が「デジタル署名されていません」というエラーになる。PowerShell で次を1回だけ打つ（今のユーザだけの設定。管理者の権限は要らない）。

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

   RemoteSigned は、「インターネットから取ってきたスクリプトは署名が要る。自分のPCにあるスクリプトは動かしてよい」という設定。この設定を変えたくない人は、代わりに `npm.cmd`・`npx.cmd` と打つか、コマンドプロンプト（cmd）で打つ。

**完了条件**：`node -v` が `v24.12.0`、`npm -v` が版を表示する。

### 手順9：画面の部品を入れる

Client のフォルダで次を打つ。

```powershell
npm install
npx playwright install chromium
```

**完了条件**：どちらもエラーなく終わる。

### 手順10：画面のテストを確かめる

開発用に起動したサーバーがあれば、先に止める。Playwright は、すでに動いているサーバーをそのまま使うため、開発用のデータベース（equipment_dev）でテストが動いてしまう。

Client のフォルダで次を打つ。

```powershell
npx playwright test
```

テスト用の設定（equipment_test）でサーバーと画面が自動で起動し、テストが動く。

**完了条件**：すべて `passed` になる。

### 手順11：Eclipse に Server を取り込む

1. 「ウィンドウ」→「設定」→「Gradle」で、「Java ホーム」に Java 21 のフォルダを指定する（Gradle 9 は Java 17 以上で動く。取り込みでエラーが出るときは、ここを確かめる）。
2. 「ファイル」→「インポート」→「Gradle」→「既存の Gradle プロジェクト」で、Server のフォルダを指定する。
3. プロジェクト名が、フォルダ名と同じ `EquipmentManagementSystem_Server` になっていることを確かめる（Server の CLAUDE.md 2章）。
4. Eclipse に Lombok を入れる（CLAUDE.md 3章）。Lombok は、Gradle で組み立てるときは自動で働くが、Eclipse は自分で Java を読むので、別に入れないと、Lombok が作るメソッド（`getName()` など）が見つからないという赤い×が出る。
   1. Server のフォルダで `.\gradlew.bat -q dependencyInsight --dependency lombok --configuration compileClasspath` と打ち、1行目に出る版（例：`org.projectlombok:lombok:1.18.48`）を確かめる。
   2. その版の lombok.jar を Maven Central（ライブラリの公式の置き場所）から取ってくる。ブラウザで `https://repo1.maven.org/maven2/org/projectlombok/lombok/<版>/lombok-<版>.jar` を開く（例：`https://repo1.maven.org/maven2/org/projectlombok/lombok/1.18.48/lombok-1.18.48.jar`）。置き場所は、`<development>` の中など、消さない場所にする（Eclipse が起動するたびに読むため）。
   3. Eclipse を閉じてから、取ってきたフォルダの PowerShell で `java -jar lombok-<版>.jar` と打つ。Lombok の画面が開く。
   4. Eclipse が一覧に出たら、チェックを付ける。出なければ「Specify location...」で `eclipse.exe` を選ぶ（Pleiades All in One なら `pleiades\eclipse\eclipse.exe`）。
   5. 「Install / Update」を押し、「Install successful」と出たら「Quit Installer」で閉じる。

## 5. 今ある MySQL・Docker の MySQL の扱い（すでに入れている人）

3306番は、MySQL が1つしか使えない。次の人は、手順4・5の前に、ここで片づける。テーブルは Flyway が作り直すので、どの MySQL にも残すべきデータはない（開発用に手で入れたデータは消える。要るものがあれば、先に人が控える）。

1. サーバー（bootRun・Eclipse）と画面を止める。
2. **Docker で MySQL を動かしていた人**（2026-11-09〜11-14 の手順）
   - PowerShell で `docker stop equipment-mysql` を打って、コンテナ（Docker の箱）を止める。要らなくなったら、`docker rm equipment-mysql` で消す。
   - データの置き場所（ボリューム）も、要らなければ `docker volume rm equipmentmanagementsystem_server_mysql-data` で消す（**中のデータは消える**）。名前は `docker volume ls` で確かめる。
   - Docker Desktop は、ほかで使わなければ、Windows の「設定」→「アプリ」からアンインストールしてよい。自分のユーザーのフォルダの `.wslconfig` も、ほかで WSL を使わなければ消す。
   - Server の `.env` は、もう使わない。消してよい（Git には入らないので、残っていても害はない）。
   - 最新の release/main を取ってくると、Server の `compose.yaml` などが消える。取ってくる前に Docker を止めておく。
3. **PC に直接入れた MySQL が、すでにある人**（例：MySQL84、MYSQL80）。`Get-Service *mysql*` で、名前と状態を確かめる。
   - 8.4.13 のサービスが止まっているだけなら、そのまま使える。管理者の PowerShell で `Set-Service MySQL84 -StartupType Automatic` と `Start-Service MySQL84` を打ち（名前は確かめたものにする）、`mysql --version` が `8.4.13` を含むことを確かめて、手順5へ進む（手順4は飛ばす）。データベースとユーザが、前に作ってあるなら、手順5の SQL も要らない（`mysql -u equipment -p -e "SHOW DATABASES;"` で、`equipment_dev` と `equipment_test` が出ればよい。`::1` などの足りないユーザは、手順5の SQL から、足りない行だけ流す）。
   - 8.0 が入っているなら、次の「8.0 から 8.4 への入れ替え」を行う。

### 8.0 から 8.4 への入れ替え

MySQL 8.0 は、開発元のサポートが終わっている（1.1）。

1. Windows の「設定」→「アプリ」から、MySQL Server 8.0 をアンインストールする。
2. `Get-Service *mysql*` で、8.0 のサービス（例：MYSQL80）がなくなったことを確かめる。残っていたら、MySQL Installer（8.0 を入れたときの道具）でも消す。
3. 8.0 のデータのフォルダ（初期値は `C:\ProgramData\MySQL\MySQL Server 8.0`。ProgramData は隠しフォルダ）は、アンインストールしても残る。要らなければ人が消す。
4. Windows の環境変数 Path から、`C:\Program Files\MySQL\MySQL Server 8.0\bin` を外す。
5. 手順4〜7を行う（MySQL 8.4.13 を development フォルダに入れる）。

**完了条件**：`Get-Service *mysql*` で、`Running` の MySQL が、8.4.13 の1つだけになる（Docker の MySQL も動いていない：`docker ps` に `equipment-mysql` が出ない）。

## 6. つまずきやすい点

| 出たもの | 原因と直し方 |
|---|---|
| `mysql --version` が 8.0 を表示する | Path に 8.0 の bin が残っているか、8.4 の bin より上にある。手順4-6と5章の5を確かめ、PowerShell を開き直す |
| 4-4 や 4-5 で `VCRUNTIME140.dll` が見つからない | MySQL が使う Windows の部品（Microsoft Visual C++ 再頒布可能パッケージ）がない。Microsoft の公式サイトから入れる（管理者の権限が要る） |
| 4-4 で「datadir の中にファイルがある」というエラー | 前に初期化した `<development>\mysql-data\equipment` が残っている。中身が要らないことを確かめてから消し、やり直す |
| 4-5 で `Install/Remove of the Service Denied!` | PowerShell を管理者として開いていない。「管理者として実行」で開き直す |
| 4-5 で `The service already exists!` | 同じ名前（MySQL84）のサービスがもうある。インストーラーで 8.4 を入れたことがあるなら、そのまま使ってよい（1.1 の説明） |
| `net start MySQL84` で起動しない | 3306番を、ほかの MySQL（8.0 のサービスなど）がもう使っている。`Get-Service *mysql*` で動いているほかの MySQL を止める。my.ini の `basedir`・`datadir` の書き間違い（`\` でなく `/`）も確かめる。`<development>\mysql-data\equipment` の中の `.err` の名前のファイルに、理由が書いてある |
| テストがほぼ全部失敗し、`ConflictingBeanDefinitionException`（例：bean name 'healthMapper' … conflicts）と出る | 同じ名前のクラスが、古い場所と新しい場所の両方にある。成果物の zip を反映したときに、変更ファイル一覧.md の「消した」ファイルを消し忘れている。そのファイルを消してから、もう一度テストする |
| テストの名前などの日本語が、PowerShell の画面で文字化けする | 画面の文字コードの違いで、テストの結果には影響しない。レポート（build/reports/tests/test/index.html）では正しく読める。気になるときは、テストの前に `chcp 65001` を打つと直ることが多い |
| `java -version` が 21 でない | Path の中で、ほかの版の Java が上にある。Java 21 のフォルダを上に移し、PowerShell を開き直す |
| `npm`・`npx` が「デジタル署名されていません」 | PowerShell の実行ポリシー。手順8の2 |
| `Access denied for user '（Windows のユーザー名）'@'localhost' (using password: NO)`（例：テストがほぼ全部失敗し、原因に FlywaySqlUnableToConnectToDbException と出る） | secret.yml がない、または置き場所が違う。ユーザ名が書かれていないので、Windows のユーザー名でつなごうとしている。手順6のとおり、Server のフォルダ（build.gradle と同じフォルダ）に secret.yml を作る |
| `Access denied for user 'equipment'` | secret.yml のユーザ名・パスワードが、手順5で作ったものと違う。または secret.yml の場所が違う（build.gradle と同じフォルダに置く） |
| `Communications link failure` | MySQL が動いていない。Windows の「サービス」で MySQL を起動する（`Start-Service MySQL84`。名前は `Get-Service *mysql*` で確かめる） |
| `Access denied for user 'equipment'@'127.0.0.1'`（または `'::1'`）。パスワードは合っている | 手順5で、`equipment` のユーザを、3つの呼び名（localhost・127.0.0.1・::1）のすべてで作っていない。`mysql -u root -p` でつなぎ、`SELECT user, host FROM mysql.user;` で確かめ、足りない行だけ、手順5の `CREATE USER` と `GRANT` を流す |
| `net start` や起動のときに、3306番がすでに使われている | Docker で動かしていた MySQL（`equipment-mysql`）が、動いたままになっている。5章の2 |
| サーバーが起動しない。「最初の総務の担当者のメールアドレス（app.initial-admin-email）が設定されていません」と出る | secret.yml の `app.initial-admin-email` が空。メールアドレスの形の値を書く（手順6の3） |
| `Public Key Retrieval is not allowed` | MySQL 8.4 のパスワードのやり取りの決まり（caching_sha2_password）による。DBViewer などの道具でつなぐときは、接続の文字列の後ろに `?allowPublicKeyRetrieval=true` を足す（アプリの設定は変えない） |
| `Port 8080 was already in use` | 8080番を使う別のアプリ（起動したままのサーバーなど）がある。止めてから起動する |
| Playwright のテストが、開発用のデータで動く・データが消える | 開発用に起動したサーバーを、Playwright がそのまま使った。止めてから `npx playwright test` |
| Eclipse で取り込めない・名前の食い違いのエラー | プロジェクト名とフォルダ名が違う。settings.gradle の `rootProject.name` がフォルダ名と同じかを確かめる（変えない決まり） |
| Eclipse の Gradle で Java のエラー | 手順11の1（Gradle の Java ホームを Java 21 にする） |
| Eclipse で、`getName()` などのメソッドや、コンストラクタが見つからないという赤い×が出る（`.\gradlew.bat test` は通る） | Eclipse に Lombok が入っていない、または版が古い。手順11の4 |
| `.\gradlew.bat mybatisGenerator` で `secret.yml がない` | 手順6の secret.yml を作る。テーブルは開発用のデータベース（equipment_dev）から読むので、先に bootRun で1回起動しておく |

## 7. 毎日の開発の始め方

- MySQL は、PCを起動すると自動で動く（Windows のサービス）。
- サーバー：Server のフォルダで `.\gradlew.bat bootRun`、または Eclipse で EquipmentApplication を右クリック →「実行」→「Spring Boot アプリケーション」。
- 画面：Client のフォルダで `npm run dev` → http://localhost:5173 を開く。
- Claude Code：Server か Client のフォルダで `claude --add-dir ../EquipmentManagementSystem_Document`。

## 8. Claude Code に案内してもらう場合

1. 手順1・2は人が行う（Claude Code を入れ、リポジトリを並べる）。
2. Document のフォルダで `claude` と打って起動し、`/env-setup` と打つ。Server・Client がまだ動かなくても使える。
3. Claude Code が、終わっていない手順を見つけて1つずつ案内する。インストールや管理者の操作は人が行い、終わったら Claude Code が確かめのコマンドを動かす。
4. パスワードは会話に書かない（2章）。

## 9. 版を上げるとき

1. 2人で相談して、新しい版を決める。MySQL は、本番（RDS）で使える 8.4 系の版から選ぶ。
2. 1.1 の表と、手順の中の版・ファイル名・フォルダ名・MD5 を書き換える。
3. env-setup の skill（Document の .claude/skills/env-setup/SKILL.md）の版も合わせて直す。
   - Spring Boot の版を上げると、Lombok の版も変わることがある。そのときは、各自が手順11の4で、Eclipse の Lombok を同じ版に入れ直す。
4. 1人が自分のPCで入れ替え、4章のチェックリストがすべて通ることを確かめてから、もう1人に知らせる。

MySQL を 8.4 系の中で上げる場合（例：8.4.13 → 8.4.14）、データはそのまま使える。新しい版の zip を `<development>` に展開し、my.ini を写して `basedir` を直し、サービスを登録し直す（`net stop MySQL84` → 古い版の `mysqld.exe --remove MySQL84` → 新しい版で 4-5）。datadir はそのまま使う。
