## 4. 処理フロー

1. 共通の LoginRefreshFilter（common.md 3.10）が、APIを呼ぶたびに auth の LoginUserRefresherImpl#currentPermissions で、ログインしている人を読み直す（R-3・R-4）。
   - ユーザが削除されている、または session_valid_after がログインした日時より後なら、セッションを捨て、ログインしていない扱いにする（→ 9章の No.1）。
   - そうでなければ、今の権限項目でログイン状態を作り直す（この API の間だけ。セッションの中身は変えない）。
2. MeController が受け取る。`@PreAuthorize("isAuthenticated()")` でログインしているかを確かめる。
3. MeController が `@AuthenticationPrincipal LoginUserId` のユーザIDで MeService#me を呼ぶ（ほかの機能と同じ受け取り方。common.md 3.10）。
4. MeServiceImpl が UserMapper#selectById・RoleMapper#selectNameById・RolePermissionMapper#selectPermissionCodesByRoleId・PermissionMapper#selectSortedCodes を読み、MeResponse を作る。ユーザが見つからない（1 と 4 の間に削除された）ときは UnauthorizedException（「ログインしてください。」）。
5. `ApiResponse.ok(MeResponse)` で返す。

## 7. DB操作仕様

| No. | mapper のメソッド | 操作 | テーブル | 条件 | 読む・書く列 | 件数 |
|---|---|---|---|---|---|---|
| 1 | UserMapper#selectById | SELECT | users | id = ? AND deleted_at IS NULL | id, name, email, password_hash, role_id, locked_at, session_valid_after | 0〜1件 |
| 2 | RoleMapper#selectNameById | SELECT | roles | id = ? | name | 1件 |
| 3 | RolePermissionMapper#selectPermissionCodesByRoleId | SELECT | role_permissions | role_id = ? | permission_code | 0〜18件 |
| 4 | PermissionMapper#selectSortedCodes | SELECT | permissions | code IN (…) ORDER BY sort_order | code | 0〜18件 |

- 4章の1（APIを呼ぶたびの読み直し）では、1 と 3 だけを出す（並び順は要らない）。
