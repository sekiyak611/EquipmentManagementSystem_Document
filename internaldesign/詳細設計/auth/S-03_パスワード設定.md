## 2. 画面レイアウト

### 2.1 画面の絵

写したもと：画面設計.md v1.1 の6章

```
[備品管理]
パスワードの再設定        ← ユーザ登録のリンクから開いたときは「パスワードの設定」
  yamada@example.com      ← 対象のメールアドレス（表示のみ）
  新しいパスワード       [                    ] (目のマーク)
  新しいパスワード（確認）[                    ] (目のマーク)
  ・8文字以上、64文字以内
  ・使える文字：半角の英字・数字・記号・スペース
  [        設定する        ]
```

リンクが使えないとき（画面設計 6章「開いたときの確かめ」）：入力欄の代わりに、次を出す。

```
[備品管理]
  このリンクは使えません。有効期限が切れたか、すでに使われています。
  パスワード再設定の依頼へ
```

## 4. 入力チェック仕様

写したもと：画面設計.md v1.1 の6章・8章（メッセージは一字も変えずに写す）

| 項目 | 決まり | メッセージ | 確かめるとき | サーバーでも確かめるか |
|---|---|---|---|---|
| 新しいパスワード | 空でない | 「新しいパスワードを入力してください」 | 「設定する」を押したとき | はい（A-06 の6章） |
| 新しいパスワード | 半角の英字・数字・記号・スペース（0x20〜0x7E）だけ | 「パスワードに使えるのは、半角の英字・数字・記号・スペースです」 | 同上 | はい |
| 新しいパスワード | 8文字以上 | 「パスワードは8文字以上で入力してください」 | 同上 | はい |
| 新しいパスワード | 64文字以内 | 「パスワードは64文字以内で入力してください」 | 同上 | はい |
| 新しいパスワード | メールアドレス・システム名・よく使われるパスワードと同じでない | 「このパスワードはよく使われているため、使えません。別のパスワードにしてください」 | サーバーだけ（一覧を持たないため。A-06 が 400 で返したとき、入力欄の下に出す） | はい（A-06 の5章 No.5） |
| 新しいパスワード（確認） | 新しいパスワードと同じ（空のときも、違うものとして扱う） | 「確認用のパスワードが一致しません」 | 「設定する」を押したとき | はい |

- 新しいパスワードの1つの欄に出すのは、1つだけ。順番は上の表のとおり（空 → 使えない文字 → 短い → 長い。サーバーと同じ。A-06 の12章 No.2）。
- 画面で誤りがあれば、API を呼ばずに入力欄の下に出す。サーバーが 400（errors あり）を返したときも、errors を入力欄の下に出す。
- 入力中にも、「決まりの横」に、満たしているかを出す（画面設計 6章）。6章のとおり。

## 6. 画面状態・表示条件

|---|---|---|
| 確かめている間 | 何も出さない（文なし） | 画面設計にないため、文のない表示にした |
| リンクが使える | 入力欄を表示する。見出しは、用途が REGISTER のときだけ「パスワードの設定」、ほかは「パスワードの再設定」 | 画面設計 6章 |

| 確かめられなかった（つながらない・500 など） | 赤の帯に、サーバー（または common/api）の文。入力欄は出さない | 画面設計にない。リンクが使えるか分からないため、入力欄を出さない（10章の No.5） |

| 入力中の様子 | 目のマークで文字が見える。貼り付け・自動入力は止めない | 画面設計 8章 |
| 処理中 | 「設定する」を押せない | 画面設計 1.3 |
| ページを開いている間 | リンクの合言葉を含むアドレスが、移った先に伝わらないようにする（`<meta name="referrer" content="no-referrer">`。この画面を開いている間だけ付ける） | 機能一覧 6章の5（10章の No.6） |

## 10. 設計書にない判断

| No. | 判断 | 理由 | 外から見えるか | 人の確認 |
|---|---|---|---|---|
| 1 | URL を `/password-set?token=<合言葉>` にした | 画面設計に S-03 の URL がない。S-02 の `/password-reset` に合わせた。DM のリンクと同じアドレス（A-04 の12章 No.1、common.md 10章 No.22） | はい | 済（2026-11-15。A-04 の PR で確認） |
| 2 | 合言葉は、アドレスの `token` から読んで、A-05・A-06 に JSON の中で送る | API設計 3.1（アドレスに入れると、サーバーのアクセスの記録に残るため、JSON の中で送る）。リンク自体は、DM で届くアドレスなので、アドレスに入る | いいえ | ― |
| 3 | 決まりの横の「✓」：「8文字以上、64文字以内」は、8文字以上64文字以内のとき。「使える文字」は、1文字以上あり、すべて半角の英字・数字・記号・スペースのとき。それ以外は「・」 | 画面設計 6章は例（「8文字以上」の前に✓）だけを決めている | はい | まだ |
| 4 | 「設定する」を押したときに、リンクが使えなくなっていたとき（A-06 が 400・errors なし）は、入力欄を、「使えません」の表示に変える | 画面設計 6章は、開いたときの確かめだけを決めている。ほかで先に使われたリンクで、続けて入力させても、必ず断られるため | はい | まだ |
| 5 | 開いたときの確かめが、つながらない・500 のときは、赤の帯だけを出し、入力欄は出さない | 画面設計に決まりがない。リンクが使えるかが分からないので、入力欄を出さない。もう一度開けば、やり直せる | はい | まだ |
| 6 | この画面を開いている間、`<meta name="referrer" content="no-referrer">` を付ける | 機能一覧 6章の5（Referrer-Policy を no-referrer にする）の担当を、S-03 とした（common.md 3.14 の申し送り）。画面を離れたときに外す。Server の HTTP の見出し（Referrer-Policy）は、全体の設定になるので、この作業では変えない | いいえ | まだ |
| 7 | 設定できたあと、S-01 に移るとき、履歴を置き換える（`replace`） | 合言葉を含むアドレスが、戻る操作で開けないようにするため（使用済みなので、開いても使えないが、念のため） | いいえ | ― |
| 8 | 設定できたあとの緑の帯を、S-01 に移ってから出す（S-03 で出して、そのまま S-01 でも出る） | 帯は画面全体で1つ（MessageProvider）で、画面を移っても残る（5秒で消える） | はい | ― |
| 9 | 見出しは、用途が REGISTER のときだけ「パスワードの設定」にする（RESET・LOCK は「パスワードの再設定」） | 画面設計 6章は「ユーザ登録のリンクから開いたときは「パスワードの設定」」と決めている。ロックのリンクは、再設定の仲間として扱った | はい | まだ |
| 10 | 「使えません」の表示には、見出しを付けない | 画面設計 6章に、見出しの文がない（新しい文は足さない） | はい | まだ |
